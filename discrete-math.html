1.1. Множества, отношения и отображения

Вопрос / терминОпределение, смысл и пример
Множество и способы заданияМножество — совокупность объектов, рассматриваемых как целое. Задаётся перечислением, свойством или формулой. Пример: A={2,4,6} или «чётные числа меньше 8».
Для понимания: Множество задаёт не порядок элементов, а сам факт их принадлежности группе. Поэтому {1,2,3} и {3,2,1} — одно множество, а повтор элемента ничего не меняет.
Диаграммы ВеннаГрафическое изображение множеств областями: пересечение кругов — общие элементы, объединение — всё внутри кругов. Пример: студенты, знающие C#, и студенты, знающие Python.
Для понимания: Диаграмма помогает увидеть смысл операций: пересечение показывает одновременную принадлежность, а дополнение — всё, что осталось вне выбранного множества внутри универсального.
Операции над множествамиA∪B — всё из A и B; A∩B — общее; A\B — элементы A без B; A△B — элементы только одного множества; дополнение Ā=U\A. Пример: пользователи двух приложений.
Для понимания: Не путай разность и симметрическую разность: A\B смотрит только на элементы A, а A△B берёт элементы обеих сторон, кроме общих.
Декартово произведениеA×B — все упорядоченные пары (a,b), где a∈A, b∈B. Пример: студенты × дисциплины — все возможные пары «студент–дисциплина».
Для понимания: Главная особенность — пары упорядочены. Из A×B строятся отношения: мы берём не все пары, а только те, которые удовлетворяют нужной связи.
ОтношениеБинарное отношение — любое подмножество A×B, то есть выбранные пары связанных объектов. Пример: «человек подписан на канал»; один человек может быть связан с несколькими каналами.
Для понимания: Отношение шире функции: один элемент может быть связан с несколькими объектами или вообще ни с одним. Функция вводит дополнительное требование однозначности.
Свойства отношенийРефлексивность: aRa. Симметричность: aRb⇒bRa. Антисимметричность: aRb и bRa⇒a=b. Транзитивность: aRb и bRc⇒aRc. Пример: ≤ рефлексивно, антисимметрично и транзитивно.
Для понимания: Симметричность и антисимметричность не являются противоположностями. Антисимметричность не запрещает обратную связь вообще — она разрешает её одновременно только для одинаковых элементов.
Разбиение множестваНабор непустых непересекающихся частей, объединение которых даёт всё множество. Пример: распределение студентов по учебным группам.
Для понимания: Каждый элемент должен попасть ровно в одну часть. Если части пересекаются или какой-то элемент потерян, это уже не разбиение.
Отношение эквивалентностиРефлексивное, симметричное и транзитивное отношение. Оно делит множество на классы эквивалентности. Пример: числа одной чётности.
Для понимания: Эквивалентность формализует идею «одинаковы по выбранному признаку». Все эквивалентные элементы собираются в один класс.
Отношение порядкаНестрогий порядок рефлексивен, антисимметричен и транзитивен. Частичный порядок допускает несравнимые элементы, линейный — любые два сравнимы. Пример: ⊆ — частичный порядок, ≤ — линейный.
Для понимания: Порядок нужен для сравнения элементов. В частичном порядке некоторые элементы могут быть несравнимы, как два множества, ни одно из которых не входит в другое.
Отображение (функция)Специальное отношение: каждому элементу области определения соответствует ровно один результат. Пример: каждому студенту назначен один номер студенческого билета.
Для понимания: У каждого входа должен существовать ровно один выход. Один и тот же выход разрешено назначать разным входам — это всё ещё функция.
Инъекция, сюръекция, биекцияИнъекция — разные входы имеют разные выходы; сюръекция — все элементы множества выходов использованы; биекция — оба свойства. Пример биекции: каждому месту назначен ровно один студент.
Для понимания: Запоминалка: инъекция — «не склеивает входы», сюръекция — «покрывает весь выход», биекция — взаимно-однозначное соответствие.
Операции над функциямиКомпозиция (g∘f)(x)=g(f(x)) — последовательное применение функций. Обратная функция отменяет исходную и существует для биекции. Пример: рубли → доллары → евро.
Для понимания: При композиции функции применяются справа налево: сначала f, затем g. Обратная функция существует только там, где каждому выходу соответствует единственный вход.

1.2. Основные понятия теории графов

Вопрос / терминОпределение, смысл и пример
ГрафГраф G=(V,E) состоит из вершин V и рёбер E. Пример: города — вершины, дороги — рёбра.
Для понимания: Граф описывает не внешний вид рисунка, а структуру связей. Одну и ту же сеть можно нарисовать по-разному, но множество вершин и рёбер останется тем же.
Ориентированный и неориентированный графВ ориентированном графе связь имеет направление, в неориентированном — нет. Пример: подписка направленная, дружба обычно ненаправленная.
Для понимания: В ориентированном графе A→B не означает B→A. Для улицы с односторонним движением направление критично, а для двусторонней дороги — нет.
Смежность, инцидентность, степеньВершины смежны, если соединены ребром. Ребро инцидентно своим концам. Степень вершины — число её рёбер. Пример: число прямых дорог из города.
Для понимания: Смежность относится к паре вершин, инцидентность — к ребру и вершине. Степень показывает, сколько непосредственных связей имеет вершина.
Маршрут, цепь и путьМаршрут допускает повторение вершин и рёбер; цепь не повторяет рёбра; путь не повторяет вершины. Пример: прогулка может дважды пройти через одну площадь.
Для понимания: Это вложенные ограничения: маршрут почти ничего не запрещает, цепь запрещает повтор рёбер, путь — повтор вершин. Поэтому каждый путь является маршрутом, но не наоборот.
ЦиклЗамкнутый путь: начало и конец совпадают, промежуточные вершины не повторяются. Пример: дом → магазин → парк → дом.
Для понимания: Цикл возвращается в начало, но не должен повторять промежуточные вершины. Он показывает замкнутый обход части графа.
СвязностьГраф связный, если между любой парой вершин существует путь, возможно через промежуточные вершины. Отдельные связные части — компоненты связности.
Для понимания: Вершины не обязаны иметь прямое ребро. Достаточно, чтобы между ними существовала последовательность промежуточных вершин.
Планарный графГраф планарный, если его можно изобразить на плоскости без пересечения рёбер, кроме общих концов. Пересечения на одном рисунке ещё не означают непланарность.
Для понимания: Планарность — свойство графа, а не конкретного рисунка. Даже если рёбра сейчас пересекаются, граф остаётся планарным, если его можно перерисовать без пересечений.

1.3. Переключательные функции

Вопрос / терминОпределение, смысл и пример
Переключательная функция (ПФ)Функция f:{0,1}ⁿ→{0,1}; входы и выход принимают только 0 или 1. Пример: лампа горит, если включены оба переключателя: f=A∧B.
Для понимания: ПФ моделирует цифровую логику: 0 и 1 можно понимать как «нет/есть сигнал», «ложь/истина» или «выключено/включено».
Способы задания ПФТаблица истинности, формула, вектор значений, логическая схема, ДНФ/КНФ, карта Карно. Пример AND: 00→0, 01→0, 10→0, 11→1.
Для понимания: Все способы описывают одну и ту же функцию. Таблица удобна для проверки всех наборов, формула — для вычисления, схема — для аппаратной реализации.
ДНФ и КНФДНФ — «ИЛИ из И»: (A∧B)∨(¬A∧C). КНФ — «И из ИЛИ»: (A∨B)∧(¬A∨C). СДНФ строится по единицам, СКНФ — по нулям.
Для понимания: В совершенной форме каждый элементарный член содержит все переменные. СДНФ восстанавливают по строкам с единицами, СКНФ — по строкам с нулями.
Специальные разложения ПФРазложение Шеннона: f=x∧f(1)∨¬x∧f(0), то есть отдельно случаи x=1 и x=0. Также функцию можно представить полиномом Жегалкина через XOR и AND.
Для понимания: Разложение Шеннона раскладывает функцию на два сценария по одной переменной. Это похоже на конструкцию if: отдельно вычислить результат при x=0 и при x=1.
Неполностью определённая ПФДля некоторых входов результат не задан или неважен; их обозначают X, *, «–» (don’t care). Пример: код 101 никогда не поступает, поэтому выход выбирают свободно.
Для понимания: Неопределённое значение не означает ошибку. Оно означает, что данный вход невозможен или его результат не важен для работы устройства.
Минимизация ПФУпрощение формулы без изменения обязательных значений. Методы: булева алгебра, карты Карно, Квайн—Мак-Класки. Пример: (A∧B)∨(A∧¬B)=A.
Для понимания: Упрощение должно сохранять таблицу истинности на всех обязательных наборах. Цель — меньше операций, логических элементов и задержек.
Минимизация частной ПФDon’t care разрешено считать 0 или 1 — выбирают вариант, который сильнее сокращает выражение. На карте Карно клетку включают в группу только при пользе.
Для понимания: Неопределённые клетки — резерв для упрощения. Их разрешено включать в группу Карно, но не нужно покрывать обязательно.

1.4. Функциональная полнота

Вопрос / терминОпределение, смысл и пример
Функционально полный базисНабор операций, через который суперпозицией можно выразить любую булеву функцию. Пример: {¬,∧,∨}, {¬,∧} или {¬,∨}.
Для понимания: Полнота означает выразительную мощность, а не краткость. Через полный базис можно построить любую функцию, хотя выражение иногда получится длинным.
Теорема ПостаСистема полна тогда и только тогда, когда она целиком не лежит ни в одном из классов T₀, T₁, S, M, L: сохраняющих 0, сохраняющих 1, самодвойственных, монотонных и линейных.
Для понимания: Чтобы доказать полноту, нужно «выйти» из каждого из пяти классов. Для каждого класса должна найтись хотя бы одна функция набора, которая его свойство нарушает.
Штрих Шеффера (NAND)A|B=¬(A∧B). Один NAND образует полный базис: ¬A=A|A, затем можно получить AND и OR. Пример: схема только из NAND-вентилей.
Для понимания: NAND удобен тем, что из одного типа элемента можно собрать всю цифровую логику. Сначала через A|A получают НЕ, затем остальные операции.
Стрелка Пирса (NOR)A↓B=¬(A∨B). Один NOR также функционально полон: ¬A=A↓A, затем выражаются OR и AND.
Для понимания: NOR действует аналогично NAND, но начинается с отрицания ИЛИ. Он тоже образует одноэлементный функционально полный базис.

1.5. Разрешимость и схемы алгоритмов

Вопрос / терминОпределение, смысл и пример
Разрешимая проблемаСуществует алгоритм, который для любого допустимого входа завершается и выдаёт правильный ответ. Пример: определить, чётно ли целое число.
Для понимания: Ключевое требование — алгоритм должен завершаться на каждом допустимом входе, а не только на удобных примерах.
Полуразрешимая проблемаДля положительного ответа алгоритм остановится, а для отрицательного может работать бесконечно. Пример: распознавание слов, принимаемых машиной Тьюринга.
Для понимания: Положительный ответ можно подтвердить конечным вычислением. При отрицательном ответе процедура может никогда не остановиться, поэтому это слабее полной разрешимости.
Алгоритмически неразрешимая проблемаНе существует универсального алгоритма, всегда завершающегося с правильным ответом. Классический пример — проблема остановки программы.
Для понимания: Неразрешимость относится не к медленной программе, а к принципиальному отсутствию универсального алгоритма, который всегда правильно отвечает и останавливается.
Схема алгоритма (блок-схема)Графическое описание управления: овал — начало/конец, прямоугольник — действие, ромб — условие, стрелки — порядок. Пример: проверка возраста «≥18?» с двумя ветвями.
Для понимания: Блок-схема показывает поток управления: что выполняется, где проверяется условие и куда идёт выполнение дальше. Она не показывает движение самих данных подробно.
Схема потоков данныхОриентированный граф, где узлы — операции, дуги — передаваемые данные. Операция запускается, когда готовы входы. Пример: a и b → сложение → умножение.
Для понимания: Здесь главное не порядок команд, а зависимости: операция может начаться, когда появились нужные входные данные. Независимые узлы могут работать параллельно.

1.6. Логика высказываний и предикатов

Вопрос / терминОпределение, смысл и пример
Логика высказыванийРаботает с готовыми утверждениями, имеющими значение истина/ложь, и операциями ¬, ∧, ∨, →, ↔. Пример: «идёт дождь → дорога мокрая».
Для понимания: Высказывание уже имеет готовое значение истины. Внутренняя структура объектов не рассматривается: всё утверждение обозначается одной логической переменной.
Логика предикатовОписывает свойства объектов и отношения между ними. P(x) становится высказыванием после подстановки значения или квантора. Пример: Student(Саша).
Для понимания: Предикат похож на шаблон утверждения с переменными. Пока переменная свободна, это ещё не полностью определённое высказывание.
Кванторы∀x — для всех x; ∃x — существует хотя бы один x. Пример: ∀x(Student(x)→Passed(x)) — каждый студент сдал.
Для понимания: Квантор связывает переменную в своей области действия. Важно различать «для каждого существует свой» (∀x∃y) и «существует один для всех» (∃y∀x).
ИсчислениеФормальная система с алфавитом, формулами, аксиомами и правилами вывода. Пример: из A и A→B вывести B (modus ponens).
Для понимания: Исчисление задаёт механические правила доказательства. Формальный вывод проверяет форму записи и правила перехода, а не бытовую убедительность рассуждения.
НепротиворечивостьВ системе нельзя вывести одновременно A и ¬A. Иначе из противоречия можно получить любое утверждение.
Для понимания: Если система допускает одновременно A и ¬A, она теряет смысл как средство доказательства, потому что из противоречия в классической логике выводится любое утверждение.
ПолнотаВсе формулы, истинные во всех интерпретациях, могут быть доказаны средствами исчисления.
Для понимания: Полнота связывает семантику и синтаксис: всякая общезначимая формула должна иметь формальное доказательство. Не путай с функциональной полнотой булевых базисов.
Синтаксис и семантикаСинтаксис задаёт правила записи; семантика — смысл и истинность в модели. Пример: истинность ∀xP(x) зависит от области объектов и смысла P.
Для понимания: Синтаксис отвечает «правильно ли записано», семантика — «что это означает и когда истинно». Корректная формула может быть как истинной, так и ложной в разных моделях.
Клаузальная формаКонъюнкция клауз, каждая клауза — дизъюнкция литералов. Переход: убрать →, перенести ¬, вынести кванторы, сколемизировать, привести к КНФ.
Для понимания: Клауза — это ИЛИ литералов, а весь набор клауз понимается как их И. Такая форма удобна, потому что метод резолюций работает по единому правилу.
Метод резолюцийК посылкам добавляют отрицание заключения. Из P∨A и ¬P∨B получают A∨B. Пустая клауза □ означает противоречие и доказывает заключение.
Для понимания: Запоминалка: посылки + отрицание цели → клаузы → резольвенты → □. Получение пустой клаузы завершает доказательство.
Резолюции в логике предикатовНужна унификация — подбор подстановок. Пример: P(x) и ¬P(Sasha) унифицируются заменой x:=Sasha.
Для понимания: Унификация делает литералы одинаковыми подбором подстановки. После этого к ним применяется обычное правило удаления противоположных литералов.
Принцип логического программированияПрограмма задаётся фактами и правилами, а запрос доказывается унификацией, резолюцией и перебором. Пример Prolog: passed(X):-student(X).
Для понимания: В логическом программировании программист описывает знания и отношения, а система сама ищет доказательство запроса. Управление во многом превращается в логический вывод.

1.7. Специальные логики

Вопрос / терминОпределение, смысл и пример
Темпоральная логикаОписывает истинность во времени. X — следующий шаг, F — когда-нибудь, G — всегда, U — до тех пор. Пример: G(request→F response).
Для понимания: Она позволяет говорить не только «истинно сейчас», но и «будет истинно», «всегда истинно» или «истинно до наступления события». Особенно полезна для проверки поведения систем.
Модальная логикаДобавляет □ «необходимо» и ◇ «возможно». Пример: □P — P истинно во всех допустимых состояниях; ◇P — хотя бы в одном.
Для понимания: Операторы необходимости и возможности оценивают утверждение не в одном состоянии, а в наборе допустимых миров или состояний.
Нечёткая логикаИстинность задаётся степенью от 0 до 1. Пример: 28°C принадлежит понятию «жарко» со степенью 0,7.
Для понимания: Степень 0,7 не означает вероятность 70%. Она показывает, насколько объект соответствует расплывчатому понятию, например «высокая температура».
Нечёткая арифметикаОперации над нечёткими числами — значениями с диапазоном и степенями принадлежности. Пример: «около 30 минут» + «около 10 минут» ≈ «около 40 минут».
Для понимания: Нечёткое число — не одно точное значение, а множество возможных значений с разными степенями принадлежности. Результат операции тоже остаётся нечётким.
Логика ХоараТройка {P} C {Q}: если до команды C выполнено P, то после неё выполнено Q. Пример: {x=2} x=x+1 {x=3}.
Для понимания: Тройка Хоара описывает частичную корректность: если программа завершилась из состояния P, то после неё истинно Q. Для циклов ключевую роль играет инвариант.
Логическое следованиеΓ⊨A: во всех моделях, где истинны посылки Γ, истинно A. Пример: A и A→B логически влекут B.
Для понимания: Следование — семантическое отношение: невозможно, чтобы все посылки были истинны, а заключение ложно.
Принцип дедукцииПри стандартных условиях Γ,A⊢B эквивалентно Γ⊢A→B: допущение A переносится в импликацию.
Для понимания: Он позволяет заменить временное предположение A доказательством импликации A→B. Это способ вынести допущение из списка посылок внутрь формулы.
Метод резолюцийДоказательство от противного: добавить ¬A, строить резольвенты, получить □. Пример: из P и ¬P∨Q вывести Q.
Для понимания: Запоминалка: посылки + отрицание цели → клаузы → резольвенты → □. Получение пустой клаузы завершает доказательство.

1.8. Формальные и алгоритмические системы

Вопрос / терминОпределение, смысл и пример
Аксиоматическая системаСодержит алфавит, правила построения формул, аксиомы и правила вывода. Теорема — формула, полученная конечным доказательством.
Для понимания: Аксиомы принимаются без доказательства внутри данной системы. Теоремы не являются отдельными исходными правилами — они получаются из аксиом по правилам вывода.
Формальный выводПоследовательность формул, где каждая — аксиома, посылка или результат правила. Пример: A, A→B, следовательно B.
Для понимания: Каждый шаг доказательства должен быть проверяем по форме. Нельзя добавить правдоподобную фразу, если она не является аксиомой и не выведена правилом.
Метатеория формальных системИзучает систему «снаружи»: непротиворечивость, полноту, разрешимость и независимость аксиом.
Для понимания: Объектная теория доказывает формулы внутри системы, а метатеория изучает саму систему: можно ли ей доверять и что она способна доказать.
Алгоритмическая системаФормальная модель для описания алгоритмов и вычислимости. Примеры: машина Тьюринга, алгоритмы Маркова, рекурсивные функции.
Для понимания: Такие модели нужны, чтобы строго исследовать понятие вычислимости независимо от C#, Python или конкретного компьютера.
Рекурсивные функцииФормальная модель вычислимых числовых функций: строятся из базовых с помощью суперпозиции, примитивной рекурсии и минимизации. Не сводятся только к самовызову в коде.
Для понимания: В теории вычислимости термин шире обычной рекурсии в коде. Функции строятся из простейших функций по строгим операциям и задают формальную модель алгоритма.
Нормальный алгоритм МарковаРаботает со словами по упорядоченным правилам α→β; применяется первое подходящее. Заключительное правило останавливает работу. Пример: «ab»→«ba».
Для понимания: Правила проверяются в заданном порядке, и применяется первое подходящее вхождение. Поэтому перестановка правил может изменить результат алгоритма.

1.9. Формализация алгоритма и вычислимость

Вопрос / терминОпределение, смысл и пример
Формализация понятия алгоритмаИнтуитивный алгоритм заменяют строгими моделями: машиной Тьюринга, алгоритмами Маркова и рекурсивными функциями. Они эквивалентны по вычислительной мощности.
Для понимания: Строгая модель позволяет математически доказать, вычислима задача или нет. Разные классические модели дают один и тот же класс вычислимых функций.
Машина ТьюрингаБесконечная лента, головка, алфавит, состояния и функция переходов. За шаг головка читает, записывает, меняет состояние и двигается влево/вправо.
Для понимания: Состояние и прочитанный символ однозначно определяют следующий шаг. Несмотря на простоту, машина моделирует любой обычный алгоритм.
Применимость машины к словуЕсли машина доходит до состояния останова — результат вычислен. Если работает бесконечно, алгоритм на этом входе не завершился.
Для понимания: Фраза «машина применима к слову» означает, что вычисление на этом входе заканчивается. Бесконечная работа означает неприменимость к данному слову.
Тезис Чёрча—ТьюрингаВсё, что эффективно вычислимо алгоритмом, вычислимо машиной Тьюринга. Это тезис, а не формально доказываемая теорема.
Для понимания: Это утверждение связывает интуитивное понятие алгоритма с формальной машиной Тьюринга. Его нельзя доказать как обычную теорему, потому что одна сторона сформулирована неформально.
Алгоритмически неразрешимые проблемыНет универсального завершающегося алгоритма. Пример: проблема остановки — завершится ли произвольная программа на данном входе.
Для понимания: Проблема остановки показывает предел автоматического анализа программ: нельзя создать метод, который для любой программы всегда заранее определяет её завершение.
Меры сложности алгоритмаВременная сложность — число шагов; пространственная — память. Рост по n: O(1), O(log n), O(n), O(n²), O(2ⁿ).
Для понимания: Оценка O(·) описывает порядок роста затрат при увеличении входа и обычно игнорирует постоянные множители. Нужно всегда уточнять, что считается размером входа.
Легко и трудноразрешимые задачиЛегкоразрешимые обычно имеют полиномиальные алгоритмы; труднорешаемые — только сверхполиномиальные/экспоненциальные известные точные методы. Пример: бинарный поиск и коммивояжёр.
Для понимания: В теории сложности полиномиальные алгоритмы условно считают эффективными. Экспоненциальный рост быстро становится непрактичным даже при умеренном размере входа.

1.10. Классы P, NP и вычислительная сложность

Вопрос / терминОпределение, смысл и пример
Класс PЗадачи принятия решений, решаемые детерминированным алгоритмом за полиномиальное время. Пример: проверить связность графа.
Для понимания: P содержит задачи принятия решений, для которых ответ можно вычислить за n^k шагов при некоторой константе k. Это формальная модель эффективно решаемых задач.
Класс NPЗадачи, для которых предложенное решение можно проверить за полиномиальное время. P⊆NP; неизвестно, равно ли P=NP.
Для понимания: Название не означает «неполиномиальный». NP означает, что сертификат положительного ответа проверяется за полиномиальное время.
NP-трудная задачаНе менее трудна, чем любая задача из NP: каждую NP-задачу можно полиномиально свести к ней. Она не обязана принадлежать NP.
Для понимания: NP-трудность устанавливают полиномиальным сведением: быстрое решение такой задачи позволило бы быстро решать все задачи NP. Она может быть задачей оптимизации и не лежать в NP.
NP-полная задачаОдновременно принадлежит NP и является NP-трудной. Пример: SAT или задача гамильтонова цикла в форме решения.
Для понимания: Это самые трудные задачи внутри NP. Если хотя бы одна NP-полная задача получит полиномиальный алгоритм, то P=NP.
Понятие сложности вычисленийИзучает ресурсы решения: время, память и размер описания. Сложность задачи — лучший возможный расход ресурсов; алгоритма — расход конкретного метода.
Для понимания: Нужно различать сложность конкретного алгоритма и сложность самой задачи. У одной задачи могут быть разные алгоритмы с разными затратами.
Эффективный алгоритмОбычно алгоритм с полиномиальным временем и приемлемой памятью. На практике важны константы и размер входа.
Для понимания: Полиномиальность — теоретический критерий, но на практике важны степень полинома, константы, объём данных и доступная память.
Основы нечёткой логикиОбъект принадлежит нечёткому множеству со степенью μ(x)∈[0,1]. Этапы: фаззификация → правила → объединение → дефаззификация. Пример: управление вентилятором.
Для понимания: Фаззификация превращает точный вход в степени принадлежности, правила дают нечёткий вывод, а дефаззификация возвращает конкретное управляющее значение.
Элементы алгоритмической логикиЛогика программ описывает состояния и корректность. Запись Хоара {P} C {Q}; циклы доказывают через инвариант.
Для понимания: Инвариант цикла должен быть истинным до первой итерации, сохраняться после каждой итерации и вместе с условием выхода обеспечивать постусловие.
Абсолютная и относительная погрешностьАбсолютная Δ=|x̃−x|. Относительная δ=Δ/|x|. Пример: истинное 100, получено 98: Δ=2, δ=2%.
Для понимания: Абсолютная ошибка измеряется в единицах величины, относительная показывает долю ошибки. Поэтому одинаковая абсолютная ошибка может быть существенной для малого числа и незначительной для большого.
Источники погрешностейПогрешность данных, округления, усечения метода и накопления ошибок. Пример: π хранится конечным количеством знаков.
Для понимания: Ошибки могут появиться ещё до вычисления, из-за неточных входных данных, а затем увеличиваться из-за округления и особенностей численного метода.
Устойчивость алгоритмаМалые ошибки входа и округления не должны сильно увеличивать ошибку результата. Пример: вычитание близких чисел может ухудшить точность.
Для понимания: Устойчивость относится к поведению метода при малых возмущениях. Неустойчивый алгоритм способен превратить небольшую ошибку входа в большую ошибку результата.
Сложность по времени и памятиВремя — число операций, память — максимум дополнительного хранения. Пример: линейный поиск O(n) времени и O(1) памяти.
Для понимания: Иногда время уменьшают ценой дополнительной памяти и наоборот. Поэтому алгоритмы сравнивают не по одному показателю, а по компромиссу ресурсов.
Математические программные системыСредства для численных и символьных вычислений, моделирования и графиков. Примеры: MATLAB/Octave, Mathematica/Maple, Mathcad.
Для понимания: Они не заменяют понимание метода: пользователь должен выбрать модель, задать данные и оценить корректность результата, а система автоматизирует вычисления и визуализацию.
