10.1. Система баз данных, модели, реляционная алгебра и SQL

Вопрос / терминКраткий ответ + пример
База данных (БД)Организованная совокупность связанных данных для хранения и поиска. Пример: таблицы покупателей, товаров и заказов интернет-магазина.
Для понимания: Важно: БД хранит не случайный набор файлов, а сведения с общей структурой и связями между объектами.
Система баз данныхБД + СУБД + приложения + оборудование + пользователи + правила работы. Пример: банковская БД, сервер, приложение оператора и администратор.
Для понимания: Главная мысль: это вся рабочая среда вокруг данных, а не только программа СУБД.
Система управления базами данных (СУБД)Программа, которая создаёт структуру БД, хранит, ищет, изменяет, защищает и восстанавливает данные. Пример: PostgreSQL.
Для понимания: СУБД выступает посредником: приложение формулирует запрос, а СУБД решает, как безопасно найти или изменить записи.
Основные компоненты СУБДПроцессор запросов разбирает SQL; оптимизатор выбирает план; менеджер хранения работает с файлами; менеджер транзакций следит за параллельной работой и восстановлением.
Для понимания: Каталог метаданных дополнительно хранит сведения о таблицах, столбцах, ключах, индексах и правах.
Современные СУБДРеляционные: PostgreSQL, MySQL, Oracle, SQL Server, SQLite. Нереляционные: MongoDB, Redis, Neo4j. Пример: PostgreSQL — таблицы, MongoDB — документы JSON-подобного вида.
Для понимания: Выбор зависит от структуры задачи: таблицы удобны для строгих связей, нереляционные модели — для специальных форм данных и масштабирования.
Внешний уровеньПредставление данных для конкретного пользователя. Пример: курьер видит адрес заказа, но не банковские данные клиента.
Для понимания: Он скрывает лишние поля и может отличаться для разных ролей, хотя физически используется одна база.
Концептуальный уровеньОбщая логическая структура всей БД: таблицы, атрибуты, связи и ограничения. Пример: схема «Покупатель—Заказ—Товар».
Для понимания: Это единый логический чертёж базы, не зависящий от того, как файлы размещены на диске.
Внутренний уровеньФизическое хранение: файлы, страницы, записи, индексы. Пример: индекс B-tree по номеру заказа.
Для понимания: Изменение индекса или размещения файлов не должно менять смысл пользовательских запросов.
Схема БД«Чертёж» базы: таблицы, поля, типы, ключи и связи. Схема меняется редко, а данные — постоянно.
Для понимания: Не путай схему с данными: схема задаёт правила, а строки таблиц являются текущим состоянием базы.
ПодсхемаЧасть схемы для пользователя или программы. Пример: бухгалтеру доступно представление только с оплатами.
Для понимания: В реляционных СУБД подсхему часто реализуют представлением VIEW и правами доступа.
Модель данныхПравила представления структуры, связей, ограничений и операций над данными.
Для понимания: Она отвечает сразу на три вопроса: как данные устроены, как связаны и какие операции над ними допустимы.
Иерархическая модельДерево «родитель—потомок», у потомка обычно один родитель. Пример: университет → факультет → кафедра → группа.
Для понимания: Хорошо подходит для естественного дерева, но сложна, когда у объекта должно быть несколько равноправных связей.
Сетевая модельГраф связей: запись может иметь несколько родителей. Пример: преподаватель ведёт несколько дисциплин, дисциплину ведут несколько преподавателей.
Для понимания: Она гибче дерева, однако приложение обычно должно знать конкретные пути перехода между записями.
Реляционная модельДанные представлены отношениями, то есть таблицами. Строка — кортеж, столбец — атрибут, допустимые значения — домен.
Для понимания: Связи задаются значениями ключей, поэтому запрос описывает нужный результат, а не маршрут обхода записей.
Схема отношенияИмя таблицы и её атрибуты: Заказ(Код, Дата, КодКлиента, Сумма). Первичный ключ уникально определяет строку.
Для понимания: Кортеж — конкретная строка, атрибут — именованный столбец, домен — допустимое множество значений столбца.
Язык манипулирования даннымиКоманды для работы с записями: SELECT, INSERT, UPDATE, DELETE.
Для понимания: Эти команды меняют или читают строки; создание структуры относится к языку определения данных, например CREATE TABLE.
Реляционная алгебраФормальные операции над таблицами; результат снова таблица. Это теоретическая основа запросов.
Для понимания: Её замкнутость означает: результат любой операции снова можно использовать как вход следующей операции.
Выборка σОставляет строки по условию. Пример: все заказы дороже 1000 рублей; в SQL — WHERE total > 1000.
Для понимания: Выборка уменьшает число строк, но не обязана уменьшать число столбцов.
Проекция πОставляет нужные столбцы. Пример: вывести только имя и телефон клиента; в SQL — список полей после SELECT.
Для понимания: Проекция уменьшает число столбцов; в классической алгебре одинаковые результирующие строки рассматриваются как одна.
Объединение и разностьОбъединение добавляет строки двух совместимых таблиц; разность оставляет строки первой, которых нет во второй. SQL: UNION, EXCEPT.
Для понимания: Для этих операций отношения должны быть совместимы: иметь сопоставимые атрибуты и домены.
Декартово произведение и соединениеПроизведение создаёт все пары строк; соединение оставляет связанные пары. Пример: соединить клиентов с их заказами по customer_id.
Для понимания: JOIN можно понимать как произведение с последующим условием, но СУБД выполняет его более эффективно.
SQLДекларативный язык: говорим, что получить, а СУБД решает, как. Пример: SELECT name FROM customers WHERE city='Ульяновск';
Для понимания: SQL включает не только запросы, но и создание объектов, ограничения, права и управление транзакциями.

10.2. Проектирование, зависимости, декомпозиция и ER-модель

Вопрос / терминКраткий ответ + пример
Этапы проектирования БДТребования → ER-модель → таблицы и ключи → нормализация → физическое хранение → реализация и проверка.
Для понимания: Логика этапов: сначала понять предметную область, затем построить правильную структуру и только после этого выбирать индексы и физическое размещение.
ER-модельКонцептуальная модель «сущность—связь»: показывает объекты, их свойства и связи. Пример: Покупатель оформляет Заказ.
Для понимания: Она нужна до создания таблиц: сначала показывает смысл объектов, а затем переводится в реляционную схему.
СущностьСамостоятельный объект предметной области. Пример: покупатель, товар, заказ.
Для понимания: Экземпляр сущности — конкретный объект, например товар с кодом 15; тип сущности — общее понятие «Товар».
АтрибутСвойство сущности. Пример: у товара есть название и цена.
Для понимания: Атрибут должен описывать объект и иметь определённый тип или домен допустимых значений.
КлючАтрибут или набор атрибутов, уникально определяющий объект. Пример: код товара.
Для понимания: Минимальный ключ не содержит лишних атрибутов: если один из них убрать, уникальность должна потеряться.
Связь 1:1Одной записи соответствует одна запись. Пример: сотрудник — личная карточка.
Для понимания: Обычно внешний ключ размещают в одной из таблиц и ограничивают его уникальностью.
Связь 1:NОдной записи соответствует много записей. Пример: один покупатель оформляет много заказов; внешний ключ хранится в заказе.
Для понимания: Сторона N хранит внешний ключ, потому что каждая из многих записей относится к одной родительской записи.
Связь M:NМного записей связаны со многими. Реализуется промежуточной таблицей. Пример: Заказ—Товар через СтрокуЗаказа.
Для понимания: Промежуточная таблица может содержать собственные свойства связи, например количество товара или дату записи.
Функциональная зависимость X → YОдинаковому X всегда соответствует одинаковое Y. Пример: КодКлиента → ИмяКлиента.
Для понимания: Это правило предметной области, а не случайное совпадение текущих строк.
Полная зависимостьАтрибут зависит от всего составного ключа. Пример: (Заказ, Товар) → Количество.
Для понимания: Она важна при составном ключе: ни одна отдельная часть ключа не должна определять этот атрибут.
Частичная зависимостьАтрибут зависит только от части составного ключа. Пример: КодТовара → НазваниеТовара при ключе (Заказ, Товар). Устраняется во 2НФ.
Для понимания: Она создаёт повторение сведений и аномалии, поэтому зависимые поля переносят в отдельное отношение.
Транзитивная зависимостьКлюч определяет атрибут через другой неключевой атрибут. Пример: Заказ → Клиент → Телефон. Устраняется в 3НФ.
Для понимания: Проблема возникает, когда неключевое поле хранит сведения о другом самостоятельном объекте.
НормализацияРазбиение данных так, чтобы уменьшить дублирование и аномалии вставки, обновления и удаления.
Для понимания: Цель — чтобы каждый независимый факт хранился в одном месте и изменялся один раз.
Первая нормальная форма (1НФ)В каждой ячейке одно атомарное значение, нет списков. Плохо: поле «товары = мышь, клавиатура».
Для понимания: Отдельная строка должна описывать один факт, а поле — одно значение установленного типа.
Вторая нормальная форма (2НФ)Есть 1НФ и нет частичных зависимостей от составного ключа. Данные товара выносятся в таблицу Товары.
Для понимания: Если ключ состоит из одного поля, частичной зависимости от части ключа быть не может.
Третья нормальная форма (3НФ)Есть 2НФ и нет транзитивных зависимостей неключевых полей. Данные клиента выносятся в таблицу Клиенты.
Для понимания: Краткая формула для запоминания: неключевые атрибуты зависят от ключа, всего ключа и ничего, кроме ключа.
ДекомпозицияРазбиение одной большой таблицы на несколько связанных. Пример: Заказы, Клиенты, Товары, СтрокиЗаказа.
Для понимания: Таблицы после разбиения соединяют первичными и внешними ключами.
Декомпозиция без потерьПосле соединения таблиц должны восстановиться исходные данные без ложных строк.
Для понимания: Проверочный смысл: JOIN должен вернуть исходные факты, не создавая вымышленных сочетаний.
Последовательный примерИсходно в строке заказа повторяются клиент и товар. Во 2НФ отдельно выносим Товары и Заказы; в 3НФ — Клиентов. Каждый факт хранится один раз.
Для понимания: Каркас ответа: повтор данных товара — отдельная таблица Товары; повтор клиента — Клиенты; связь заказа и товара — СтрокиЗаказа.

10.3. Физическая организация, индексы, защита и сохранность

Вопрос / терминКраткий ответ + пример
Физическая организация БДСпособ размещения таблиц и индексов на носителе: база → файлы → страницы → записи → поля.
Для понимания: Логическая таблица скрывает детали хранения, а СУБД сама переводит строки в страницы и файлы.
Страница данныхБлок, который СУБД читает с диска целиком. На одной странице хранится несколько строк.
Для понимания: Диск и память читаются блоками, поэтому расположение нужных строк по страницам влияет на скорость доступа.
Неупорядоченный файл (heap)Записи кладутся в свободное место. Вставка быстрая, но поиск без индекса требует просмотра таблицы.
Для понимания: Название heap здесь не означает структуру данных «двоичная куча»; это просто хранение без порядка по ключу.
Хешированный файлХеш-функция по ключу выбирает корзину хранения. Пример: 127 mod 10 = 7 — запись идёт в корзину 7.
Для понимания: Хеш-функция определяет корзину, где ожидается запись, поэтому полный просмотр файла обычно не нужен.
КоллизияРазные ключи попали в одну корзину. Решается цепочками, дополнительными блоками или другим способом разрешения коллизий.
Для понимания: Коммутатор разделяет коллизионные домены, а полнодуплексный режим убирает состязание за общую линию.
Когда хорош хешДля точного поиска по равенству: WHERE id = 127. Для диапазона дат или сортировки подходит плохо.
Для понимания: Хеш не сохраняет порядок ключей, поэтому условия больше/меньше и сортировка для него неудобны.
Индексированный файлЕсть отдельная структура «ключ → место записи». Аналогия: предметный указатель в книге.
Для понимания: Индекс похож на оглавление: он хранится отдельно от таблицы и ведёт к нужным строкам.
B-tree индексСбалансированное дерево; подходит для =, <, >, диапазонов и сортировки. Пример: индекс по дате заказа.
Для понимания: Высота дерева мала, поэтому поиск требует чтения лишь нескольких узлов даже при большом объёме данных.
Плюс и минус индексаУскоряет чтение, но занимает место и замедляет INSERT/UPDATE/DELETE, потому что индекс тоже обновляется.
Для понимания: Индекс стоит создавать под реальные частые запросы, а не на каждый столбец подряд.
Защита БДОпределяет, кто и что может делать: аутентификация, роли, права, шифрование, аудит. Пример: аналитику разрешён только SELECT.
Для понимания: Принцип минимальных привилегий: пользователю дают только те права, которые нужны для его работы.
Доменная целостностьЗначение соответствует типу и диапазону. Пример: CHECK(price > 0).
Для понимания: Проверяется типом, NOT NULL, CHECK и другими ограничениями допустимых значений.
Целостность сущностиКаждая строка имеет уникальный ненулевой первичный ключ.
Для понимания: Первичный ключ должен быть уникальным и не иметь NULL, иначе строку нельзя однозначно определить.
Ссылочная целостностьВнешний ключ ссылается на существующую строку. Нельзя создать заказ для несуществующего клиента.
Для понимания: При удалении родителя задают правило: запретить удаление, удалить зависимые строки или обнулить ссылку.
Сохранность БДСпособность не потерять данные при сбое: транзакции, журнал, резервные копии, восстановление.
Для понимания: Она касается не правильности значений, а возможности пережить отказ оборудования, программы или ошибку пользователя.
ЖурналированиеИзменения сначала фиксируются в журнале; после сбоя СУБД повторяет завершённые операции или отменяет незавершённые.
Для понимания: Сначала сведения об изменении фиксируются в журнале, затем обновляются основные страницы — это помогает восстановлению.
Резервное копированиеКопия БД для восстановления. Важно не только создать копию, но и проверить, что она действительно восстанавливается.
Для понимания: Копию нужно не только создавать, но и проверять пробным восстановлением.

10.4. Сетевые ОС, распределённые вычисления и Web-технологии

Вопрос / терминКраткий ответ + пример
Сетевая операционная системаОС, предоставляющая сетевые службы и централизованное управление пользователями и ресурсами. Пример: Windows Server или Linux-сервер.
Для понимания: Она организует совместную работу устройств и предоставляет сетевые ресурсы как управляемые службы.
Функции сетевой ОСУчётные записи и права, файловые и печатные ресурсы, сетевые службы, удалённое управление, безопасность, резервное копирование.
Для понимания: Главный смысл — централизованно управлять пользователями, правами, службами и общими ресурсами.
Распределённые вычисленияЗадача выполняется несколькими связанными компьютерами, которые обмениваются сообщениями и выглядят как единая система.
Для понимания: Узлы имеют собственную память и процессор, поэтому координация идёт обменом сообщениями.
Пример распределённых вычисленийИнтернет-магазин: один сервер принимает запрос, другой хранит БД, третий обрабатывает оплату.
Для понимания: Если один компонент отвечает медленно или отказывает, остальные части системы могут продолжать работать частично.
Клиент—серверКлиент отправляет запрос, сервер обрабатывает и возвращает результат. Пример: мобильное приложение и сервер банка.
Для понимания: Роли различаются: клиент инициирует запрос, сервер постоянно ожидает и обслуживает множество клиентов.
Одноранговая распределённая системаУзлы могут одновременно быть клиентами и серверами. Пример: BitTorrent.
Для понимания: Ресурсы распределены между участниками, поэтому нет единственной обязательной центральной точки.
КластерНесколько компьютеров совместно решают задачу или резервируют друг друга. Пример: кластер Web-серверов за балансировщиком.
Для понимания: Для пользователя группа узлов часто выглядит как одна служба с общим адресом.
Плюсы и проблемы распределенияПлюсы: масштабирование, отказоустойчивость, совместное использование ресурсов. Проблемы: задержки, частичные отказы, синхронизация и согласованность.
Для понимания: Особенно трудно отличить медленный узел от отказавшего и поддерживать единое состояние копий данных.
Территориальная сетьОбъединяет удалённые LAN через провайдерские линии, маршрутизаторы, магистрали, VPN и центры обработки данных.
Для понимания: WAN использует инфраструктуру операторов связи и соединяет географически удалённые локальные сети.
Информационные услуги WANДоступ к Web, файлам, почте, удалённым системам, видеосвязи, облачным приложениям.
Для понимания: Сеть является транспортом, а услуги работают поверх неё на прикладном уровне.
FTPПротокол передачи файлов. Обычный FTP не шифрует данные; безопаснее SFTP или FTPS.
Для понимания: Управляющее соединение и передача данных организуются отдельно; обычный FTP небезопасен в открытой сети.
SFTPПередача файлов поверх SSH с шифрованием. Пример: загрузка файлов на сервер.
Для понимания: Несмотря на похожее имя, SFTP — отдельный протокол внутри SSH, а не просто зашифрованный FTP.
SMBСетевой доступ к общим папкам и принтерам, особенно в Windows-сетях.
Для понимания: Позволяет работать с удалённой папкой почти как с локальным диском.
SMTPОтправляет электронную почту от клиента к серверу и между почтовыми серверами.
Для понимания: SMTP отправляет почту, но для чтения и синхронизации обычно используются IMAP или POP3.
POP3Обычно скачивает письма на устройство; прост, но хуже синхронизирует несколько устройств.
Для понимания: Чаще ориентирован на загрузку писем, поэтому состояние папок между устройствами синхронизируется ограниченно.
IMAPХранит письма на сервере и синхронизирует папки между телефоном и компьютером.
Для понимания: Изменения папок и статусов писем сохраняются на сервере и видны на всех устройствах.
SSHБезопасное удалённое управление командной строкой и туннелирование. Пример: администратор подключается к Linux-серверу.
Для понимания: Шифрует аутентификацию и команды, поэтому заменил небезопасный Telnet для администрирования.
TelnetУдалённый текстовый доступ без шифрования; сегодня используется только в закрытых учебных или диагностических случаях.
Для понимания: Логины и команды передаются открыто, поэтому использовать его через Интернет нельзя.
RDPУдалённый графический рабочий стол, чаще для Windows.
Для понимания: Передаёт изображение удалённого рабочего стола и действия клавиатуры/мыши.
Виды конференц-связиАудиоконференция, видеоконференция, Web-конференция с экраном и чатом, селекторное совещание.
Для понимания: Различаются набором каналов: только звук, звук и видео либо полноценное совместное рабочее пространство.
Web-технологииКлиент-серверное взаимодействие через браузер, URL, DNS и HTTP/HTTPS.
Для понимания: Web строится на ресурсах с URL, обмене HTTP и отображении результата браузером.
Как открывается сайтБраузер узнаёт IP через DNS, устанавливает соединение, отправляет HTTP-запрос, сервер возвращает HTML/CSS/JS и данные.
Для понимания: Не путай DNS и HTTP: DNS находит адрес, а HTTP уже запрашивает содержимое у сервера.
HTMLОписывает структуру страницы: заголовки, формы, таблицы, ссылки.
Для понимания: HTML задаёт семантический каркас документа, но не выполняет серверную логику.
CSSОписывает внешний вид: размеры, расположение, цвета, адаптивность.
Для понимания: CSS отделяет оформление от структуры и позволяет адаптировать страницу под разные экраны.
JavaScriptЛогика в браузере: обработка кнопок, запросы к серверу, изменение страницы.
Для понимания: Код может выполняться в браузере, обращаться к Web API и обновлять страницу без полной перезагрузки.
Серверная разработкаОбрабатывает запросы, бизнес-логику и БД. Пример: C# и ASP.NET Core создают Web API интернет-магазина.
Для понимания: Сервер проверяет права, выполняет бизнес-правила и формирует ответ, например JSON.
Средства Web-приложенияБраузер + Web-сервер + серверное приложение + база данных + API. Пример: Nginx → ASP.NET Core → PostgreSQL.
Для понимания: Запрос проходит через несколько компонентов, но для клиента вся цепочка выглядит как единая служба.
HTTP-методыGET — получить, POST — создать/запустить действие, PUT/PATCH — изменить, DELETE — удалить.
Для понимания: Метод выражает намерение запроса; одинаковый URL может поддерживать разные действия через GET, POST и DELETE.
HTTPSHTTP поверх TLS: шифрует канал и подтверждает подлинность сервера сертификатом.
Для понимания: TLS защищает канал от чтения и подмены, но не исправляет уязвимости самого Web-приложения.

11.1. Классификация сетей, коммутация, OSI и каналы связи

Вопрос / терминКраткий ответ + пример
Классификация по масштабуPAN — личная; LAN — здание; MAN — город; WAN — страны и континенты. Пример: домашний Wi‑Fi — LAN, Интернет — WAN.
Для понимания: Масштаб влияет на расстояния, владельца инфраструктуры, задержки и используемые технологии.
Одноранговая сетьКомпьютеры равноправны и напрямую делятся ресурсами. Пример: два ПК передают файлы друг другу. Просто, но трудно администрировать большую сеть.
Для понимания: Нет постоянно выделенного центрального сервера; отказ одного узла не обязан останавливать остальные, но централизованное управление сложнее.
Клиент/серверСервер предоставляет услуги, клиенты обращаются к нему. Пример: браузер запрашивает страницу у Web-сервера.
Для понимания: Сервер предоставляет службу многим клиентам, поэтому его удобно централизованно администрировать и защищать.
Коммутация каналовНа время сеанса выделяется постоянный путь. Пример: классическая телефонная связь. Стабильно, но линия простаивает в паузах.
Для понимания: Полоса резервируется заранее на весь сеанс, даже если участники временно молчат.
Коммутация сообщенийСообщение целиком сохраняется на промежуточном узле и передаётся дальше. Большая задержка; исторический подход.
Для понимания: Сообщение хранится целиком на промежуточном узле, поэтому задержка и требования к памяти велики.
Коммутация пакетовДанные делятся на пакеты, которые совместно используют сеть. Пример: Интернет.
Для понимания: Пакеты одного сообщения могут идти разными маршрутами и собираться у получателя.
ПротоколНабор правил обмена: формат сообщений, порядок действий, реакции на ошибки. Пример: HTTP задаёт обмен браузера и сервера.
Для понимания: Он задаёт формат сообщений, порядок обмена и действия при ошибках.
Модель OSIЭталонная модель из 7 уровней. Нужна для стандартизации и поиска неисправностей.
Для понимания: Уровни разделяют обязанности: нижние передают сигнал и кадры, средние доставляют пакеты, верхние обслуживают приложения.
1. Физический уровеньПередаёт биты как сигналы: кабели, разъёмы, радиоволны. Пример: обрыв кабеля.
Для понимания: Единица передачи — бит; здесь нет IP-адресов, портов и маршрутов.
2. Канальный уровеньКадры, MAC-адреса, доступ к среде, обнаружение ошибок в локальной сети. Устройство: коммутатор.
Для понимания: Единица — кадр; коммутатор принимает решения по MAC-адресам внутри локальной сети.
3. Сетевой уровеньIP-пакеты и маршрутизация между сетями. Устройство: маршрутизатор.
Для понимания: Единица — пакет; маршрутизатор выбирает путь между разными сетями по IP-адресу.
4. Транспортный уровеньДоставка между приложениями, порты, надёжность. Протоколы: TCP и UDP.
Для понимания: Единица обычно сегмент TCP или датаграмма UDP; порты связывают данные с приложениями.
5. Сеансовый уровеньУстанавливает, поддерживает и завершает сеанс взаимодействия.
Для понимания: Отвечает за организацию диалога и контроль сеанса, а не за физическое соединение кабеля.
6. Уровень представленияПреобразует формат, кодировку, сжатие и шифрование данных.
Для понимания: Приводит данные к общему виду: кодировка, сериализация, сжатие, шифрование.
7. Прикладной уровеньСетевые услуги приложениям: HTTP, FTP, SMTP, DNS.
Для понимания: Это сетевые службы для программ, а не само пользовательское приложение целиком.
Аналоговый каналСигнал меняется непрерывно. Пример: традиционная телефонная линия.
Для понимания: Сигнал непрерывен и чувствителен к накоплению шумов; усиление усиливает и полезный сигнал, и помеху.
МодуляцияИзменение несущей по данным: амплитуды ASK, частоты FSK, фазы PSK; QAM сочетает амплитуду и фазу.
Для понимания: Несущую изменяют по закону информационного сигнала: по амплитуде, частоте или фазе.
МодемМодулятор-демодулятор: преобразует цифровые данные в сигнал канала и обратно. Пример: кабельный или сотовый модем.
Для понимания: Название происходит от «модулятор-демодулятор»: он преобразует данные в сигнал канала и обратно.
Цифровой каналПередаёт дискретные состояния, обычно 0 и 1. Лучше восстанавливает сигнал и устойчивее к накоплению искажений.
Для понимания: Регенератор может восстанавливать уровни 0 и 1, поэтому шум не обязательно накапливается как в аналоговом тракте.
Частотное разделение FDMПользователям выделяются разные полосы частот одновременно. Пример: радиостанции на разных частотах.
Для понимания: Каналы работают одновременно, но каждый использует свою полосу частот.
Временное разделение TDMОдин канал делится на временные интервалы. Пример: абоненты передают по очереди в своих слотах.
Для понимания: Каналы используют одну полосу по очереди в назначенные временные интервалы.
Характеристики проводной линииПропускная способность, затухание, помехоустойчивость, задержка, дальность, стоимость. Оптоволокно быстрое и помехоустойчивое; витая пара дешевле.
Для понимания: Пропускная способность показывает возможную скорость, задержка — время прохождения, затухание — ослабление сигнала.
Спутниковый каналСвязь через спутник; большая зона покрытия, но высокая задержка и зависимость от условий. Пример: Интернет в удалённом посёлке.
Для понимания: Большое расстояние до спутника даёт заметную задержку, особенно у геостационарных систем.
Сотовая связьТерритория делится на ячейки с базовыми станциями; при движении выполняется передача абонента между ячейками — handover.
Для понимания: Разделение территории на соты позволяет повторно использовать частоты и передавать абонента между базовыми станциями.

11.2. Кодирование, информация, контроль ошибок и сжатие

Вопрос / терминКраткий ответ + пример
Кодирование информацииПредставление сообщения последовательностью символов или битов для хранения и передачи. Пример: буква «A» кодируется числом в UTF‑8.
Для понимания: Один и тот же смысл можно представить разными кодами; код выбирают под хранение, передачу или контроль ошибок.
Количество информации по ХартлиДля N равновероятных вариантов: I = log₂N. Пример: 8 вариантов дают 3 бита, потому что 2³ = 8.
Для понимания: Формула применима, когда все N исходов равновероятны; при N=2 получаем один бит.
Энтропия ШеннонаСредняя неопределённость источника: H = −Σ pᵢlog₂pᵢ. Редкие и непредсказуемые сообщения несут больше информации.
Для понимания: Редкие события несут больше информации, а энтропия усредняет эту информацию по всем исходам.
Пример энтропииДля честной монеты H = 1 бит. Если одна сторона выпадает почти всегда, неопределённость и энтропия меньше 1 бита.
Для понимания: У честной монеты неопределённость максимальна: до броска оба исхода одинаково возможны.
Самосинхронизирующийся кодПо самому сигналу можно восстановить границы тактов без отдельного синхросигнала.
Для понимания: В потоке достаточно переходов сигнала, чтобы приёмник восстанавливал границы битов без отдельной линии такта.
Манчестерское кодированиеВ середине каждого бита обязательно есть переход уровня; направление перехода кодирует 0 или 1. Легко синхронизировать, но нужна большая полоса.
Для понимания: Переход в середине каждого бита несёт и данные, и синхронизацию, но требует большей полосы частот.
Контроль правильности передачиК сообщению добавляют избыточные контрольные данные. Получатель проверяет их и обнаруживает либо исправляет ошибки.
Для понимания: Избыточные биты не несут новых пользовательских данных, зато позволяют обнаруживать или исправлять ошибки.
Бит чётностиДобавляется один бит, чтобы число единиц было чётным или нечётным. Прост, но не обнаруживает все сочетания ошибок.
Для понимания: Обнаруживает любое нечётное число изменившихся битов, но не исправляет ошибку и может пропустить две ошибки.
Контрольная суммаБлоки данных складываются, результат передаётся вместе с сообщением. Пример: используется для быстрой проверки пакета или файла.
Для понимания: Передатчик и получатель вычисляют одно и то же значение; несовпадение показывает повреждение блока.
CRCЦиклический избыточный код: данные рассматриваются как полином и делятся на заданный полином; остаток передаётся как контроль. Хорошо обнаруживает пакетные ошибки.
Для понимания: CRC хорошо обнаруживает пакетные ошибки и часто используется на канальном уровне, например в кадрах Ethernet.
Код ХэммингаДобавляет контрольные биты так, чтобы определить позицию одиночной ошибки и исправить её.
Для понимания: Проверочные биты располагаются так, чтобы синдром указывал позицию одного ошибочного бита.
Сжатие данныхУменьшение объёма за счёт устранения избыточности. Экономит память и канал связи.
Для понимания: Сжатие устраняет избыточность представления и уменьшает объём хранения или время передачи.
Сжатие без потерьИсходные данные восстанавливаются точно. Пример: ZIP, PNG; методы RLE, Хаффмана, LZ.
Для понимания: После распаковки получаем точную копию; это обязательно для программ, документов и баз данных.
RLEПовторяющиеся символы заменяются парой «число повторов + символ». Пример: AAAAA → 5A. Хорошо для длинных серий.
Для понимания: Эффективность высокая только там, где часто встречаются длинные последовательности одинаковых значений.
Код ХаффманаЧастым символам назначаются короткие коды, редким — длинные. Используется как часть архиваторов и форматов.
Для понимания: Код является префиксным: ни одно кодовое слово не является началом другого, поэтому поток однозначно декодируется.
Семейство LZПовторяющиеся фрагменты заменяются ссылками на ранее встречавшиеся. Основа многих архиваторов.
Для понимания: Словарь повторов может строиться прямо во время обработки, без заранее известной статистики символов.
Сжатие с потерямиЧасть малозаметной информации удаляется. Пример: JPEG для фото, MP3/AAC для звука. Сжатие сильнее, но исходник не восстановить точно.
Для понимания: Допускается там, где небольшое искажение восприятия важнее точного восстановления исходных отсчётов.

11.3. Локальные сети, Ethernet, маршрутизация и TCP/IP

Вопрос / терминКраткий ответ + пример
Локальная вычислительная сетьСеть на небольшой территории: комната, здание, кампус. Обычно высокая скорость и единое администрирование.
Для понимания: Устройства обычно принадлежат одной организации и соединены Ethernet или Wi‑Fi.
Метод доступа к средеПравило, по которому устройства решают, кто сейчас может передавать по общей линии.
Для понимания: Он особенно важен, когда несколько станций делят общий физический канал.
CSMA/CDСтанция слушает линию; если свободна — передаёт; при коллизии прекращает передачу, ждёт случайное время и повторяет. Применялся в общем Ethernet с концентраторами.
Для понимания: Расшифровка: множественный доступ с контролем несущей и обнаружением коллизий.
КоллизияДве станции одновременно передали в общей среде, сигналы наложились. В коммутируемом полнодуплексном Ethernet коллизий практически нет.
Для понимания: Коммутатор разделяет коллизионные домены, а полнодуплексный режим убирает состязание за общую линию.
EthernetСемейство технологий IEEE 802.3: кадры, MAC-адреса, передача в LAN. Сегодня обычно используется звезда с коммутатором.
Для понимания: Кадр Ethernet содержит MAC-адреса отправителя и получателя, поле типа/длины, данные и контрольную сумму.
Разновидности Ethernet10 Мбит/с — Ethernet; 100 Мбит/с — Fast Ethernet; 1 Гбит/с — Gigabit Ethernet; 10 Гбит/с и выше — высокоскоростные варианты.
Для понимания: Скорость зависит от стандарта и среды: витая пара используется на коротких участках, оптика — на больших расстояниях и скоростях.
Маркерный доступПраво передачи даёт специальный кадр-маркер. Коллизий нет, но нужно обслуживать маркер.
Для понимания: Станция может передавать только после получения маркера, поэтому время ожидания более предсказуемо.
Token RingКольцевая сеть с передачей маркера. Предсказуемый доступ, но технология почти вытеснена Ethernet.
Для понимания: Логическое кольцо не обязательно означало буквально кольцевую прокладку кабеля.
FDDIДва оптоволоконных кольца с маркерным доступом, обычно 100 Мбит/с; второе кольцо повышает отказоустойчивость. Историческая магистральная технология.
Для понимания: Два кольца могли работать как основное и резервное, что повышало живучесть магистрали.
Высокоскоростная LANGigabit Ethernet и выше, обычно по витой паре или оптоволокну. Пример: 10GbE между сервером и хранилищем.
Для понимания: При больших скоростях важны производительность коммутаторов, сетевых карт и серверного хранилища.
Корпоративная сетьОбъединяет подразделения организации: LAN филиалов, WAN/VPN, серверы, доменные службы, межсетевые экраны и единое управление.
Для понимания: Она объединяет локальные сети, удалённый доступ, службы каталогов, безопасность и мониторинг.
Функции сетевого уровняЛогическая IP-адресация, выбор маршрута, передача пакетов между сетями, фрагментация в некоторых технологиях.
Для понимания: Он доставляет пакет до нужной сети, но не выбирает конкретное приложение на конечном узле.
Функции транспортного уровняСвязь между приложениями через порты, сегментация, контроль потока и ошибок. TCP надёжен, UDP быстрее и проще.
Для понимания: Порт определяет процесс-получатель; надёжность TCP реализуется подтверждениями и повторной передачей.
МаршрутизацияВыбор следующего узла для доставки IP-пакета по таблице маршрутов. Пример: домашний роутер отправляет внешние пакеты провайдеру.
Для понимания: Маршрут выбирается по адресу назначения, маске и правилу наиболее длинного совпадающего префикса.
Статическая маршрутизацияМаршруты задаёт администратор. Просто и предсказуемо, но плохо масштабируется.
Для понимания: Подходит для простой стабильной сети или маршрута по умолчанию.
Динамическая маршрутизацияМаршрутизаторы обмениваются сведениями и автоматически перестраивают маршруты при изменениях.
Для понимания: Она уменьшает ручную работу и реагирует на отказ линии, но требует обмена служебной информацией.
Дистанционно-векторный алгоритмУзел знает стоимость пути через соседей и выбирает минимальную. Идея Беллмана—Форда; пример протокола — RIP.
Для понимания: Маршрутизатор знает направление и стоимость через соседей, но не обязательно полную топологию.
Алгоритм состояния каналовКаждый маршрутизатор строит карту сети и ищет кратчайшие пути алгоритмом Дейкстры. Пример — OSPF.
Для понимания: После распространения состояния связей каждый узел независимо строит одинаковую карту сети.
Стек TCP/IP4 уровня: прикладной, транспортный, межсетевой, сетевого доступа. Это практическая основа Интернета.
Для понимания: OSI — эталонная модель из 7 уровней, TCP/IP — реально используемый стек с 4 уровнями.
IPСетевой протокол: адресует и доставляет пакеты между сетями без гарантии доставки.
Для понимания: IP работает по принципу best effort: пытается доставить пакет, но сам не гарантирует результат и порядок.
TCPНадёжное соединение: порядок, подтверждения, повторная передача, контроль потока. Пример: Web-страница или файл.
Для понимания: Перед обменом устанавливается логическое соединение; поток байтов приходит приложению в правильном порядке.
UDPПередаёт датаграммы без установления соединения и гарантий. Пример: голос, игры, DNS-запросы.
Для понимания: Нет подтверждений и повторов на уровне протокола; при необходимости их добавляет само приложение.
ICMPСлужебные сообщения об ошибках и диагностике. Пример: команда ping использует ICMP.
Для понимания: Это протокол сетевого уровня для диагностики и сообщений о проблемах доставки.
ARPВ локальной IPv4-сети узнаёт MAC-адрес по IP-адресу.
Для понимания: ARP действует только внутри локального сегмента и связывает IPv4-адрес с канальным MAC-адресом.
DHCPАвтоматически выдаёт IP, маску, шлюз и DNS-сервер. Пример: телефон подключился к Wi‑Fi и получил настройки.
Для понимания: Клиент получает настройки автоматически, поэтому администратору не нужно вручную задавать адрес каждому устройству.
DNSПреобразует доменное имя в IP-адрес. Пример: example.com → адрес сервера.
Для понимания: DNS иерархичен и распределён: локальный сервер при необходимости обращается к другим DNS-серверам.
SNMPПротокол мониторинга и управления сетевыми устройствами: счётчики, состояние интерфейсов, уведомления.
Для понимания: Агент на устройстве предоставляет параметры менеджеру мониторинга и может отправлять уведомления trap.
Адресация в InternetIP определяет узел/интерфейс, маска — границу сети, порт — приложение, DNS — имя. Пример: 192.168.1.10:443.
Для понимания: Не смешивай уровни: MAC — локальная доставка кадра, IP — доставка между сетями, порт — выбор приложения.
Частный и публичный IPЧастные адреса используются внутри сети и обычно выходят в Интернет через NAT; публичные маршрутизируются в Интернете.
Для понимания: NAT заменяет частный исходный адрес на публичный при выходе во внешнюю сеть.
Frame RelayПакетная WAN-технология с виртуальными каналами и кадрами переменной длины. Сейчас в основном историческая.
Для понимания: Работал через постоянные или коммутируемые виртуальные соединения поверх сети оператора.
ATMПередаёт ячейки фиксированного размера 53 байта, поддерживает качество обслуживания. Использовалась в магистралях и телеком-сетях.
Для понимания: Фиксированный размер ячейки уменьшал разброс задержек, что было удобно для голоса и видео.
SDHСинхронная цифровая иерархия для высокоскоростной передачи потоков по оптоволоконным магистралям с резервированием.
Для понимания: Это транспортная технология операторских сетей, а не протокол прикладного уровня.
