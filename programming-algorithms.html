6.1. Этапы решения задач, качество и жизненный цикл 10 терминов

Вопрос / терминКраткий ответ + пример
Этапы решения задачи на ЭВМПостановка → формализация → спецификация → выбор метода → алгоритм → проверка → программирование → отладка и тестирование → документирование → эксплуатация и сопровождение.
Пример: поиск максимума начинается с описания входа и ограничения «массив не пуст».
Для понимания: Код — не первый этап: сначала нужно точно понять, что решается.
Постановка задачиСодержательное описание цели, входных и выходных данных, ограничений и особых случаев.
Пример: «Дан непустой массив целых чисел. Найти максимум».
Для понимания: Отвечает на вопрос «что нужно получить?», а не «как это сделать?».
Спецификация программыТочное описание поведения программы: входов, выходов, предусловий, постусловий и реакции на ошибки.
Пример: предусловие: массив не пуст; постусловие: результат не меньше любого элемента.
Для понимания: Это договор, по которому программу потом проверяют.
АлгоритмКонечная и однозначная последовательность действий, преобразующая допустимый вход в требуемый результат.
Пример: пройти массив и обновлять текущий максимум.
Для понимания: Свойства: дискретность, определённость, конечность, результативность, массовость.
Способы записи алгоритмаСловесная запись, формулы, таблицы, блок-схемы, псевдокод и программа на языке программирования.
Пример: ветвление удобно показать блок-схемой, а шаги — псевдокодом.
Для понимания: Псевдокод точен, но не зависит от синтаксиса C#.
Критерии качестваКорректность, надёжность, эффективность, читаемость, сопровождаемость, переносимость, безопасность и удобство использования.
Пример: быстрая программа с неверными ответами некачественна.
Для понимания: Качество — совокупность свойств, а не только скорость.
Корректность и надёжностьКорректность — соответствие спецификации. Надёжность — устойчивое поведение, обработка ошибок и восстановление после сбоев.
Пример: ошибка чтения файла обрабатывается сообщением, а не аварией.
Для понимания: Корректность говорит о результате, надёжность — о стабильности работы.
ЭффективностьРациональное использование времени и памяти; оценивается временной и пространственной сложностью.
Пример: линейный поиск — O(n), бинарный — O(log n).
Для понимания: Смотрят, как растут затраты при увеличении входа.
Жизненный цикл программыЗамысел и требования → проектирование → разработка → тестирование → внедрение → эксплуатация → сопровождение → вывод из использования.
Пример: банковское приложение после выпуска обновляют и исправляют.
Для понимания: Жизненный цикл продолжается после написания кода.
Тестирование и отладкаТестирование обнаруживает несоответствие ожидаемого и фактического поведения; отладка ищет причину и исправляет её.
Пример: тест показывает неверную сумму, отладчик находит ошибку в условии скидки.
Для понимания: Тест — «где проявилось?», отладка — «почему?».

6.2. Язык высокого уровня, структурность и корректность 15 терминов

Вопрос / терминКраткий ответ + пример
Язык высокого уровняЯзык с понятными человеку конструкциями: типами, переменными, условиями, циклами, функциями и структурами данных. Компилятор или интерпретатор переводит программу в исполнимую форму.
Пример: C# компилируется для платформы .NET.
Для понимания: Программист мыслит понятиями задачи, а не кодами процессора.
Тип данныхМножество допустимых значений, операций и способ представления в памяти.
Пример: int — целые, bool — истина/ложь, string — строки.
Для понимания: Тип не только хранит значение, но и ограничивает допустимые действия.
Основные управляющие структурыСледование выполняет команды по порядку; ветвление выбирает вариант по условию; цикл повторяет действия.
Пример: прочитать число → if проверить знак → циклом обработать массив.
Для понимания: Это три базовых кирпича структурной программы.
Теорема структурыЛюбой алгоритм можно выразить комбинацией следования, ветвления и повторения без произвольных переходов.
Пример: сложный алгоритм разбивают на вложенные if и циклы.
Для понимания: Теорема обосновывает структурное программирование.
Структурное программированиеПостроение программы из понятных вложенных блоков и подпрограмм с предсказуемым входом и выходом.
Пример: заказ разделён на проверку, расчёт и сохранение.
Для понимания: Цель — сделать ход выполнения обозримым и проверяемым.
Анализ программСтатический анализ исследует код без запуска; динамический — поведение при выполнении. Анализируют корректность, ошибки и эффективность.
Пример: компилятор предупреждает об ошибке типов; профилировщик измеряет время.
Для понимания: Статический анализ видит структуру, динамический — реальные запуски.
Утверждения и тройка ХоараУтверждение описывает состояние переменных. Запись {P} S {Q} означает: из предусловия P после корректного завершения команды S следует постусловие Q.
Пример: {x=2} x=x+1 {x=3}.
Для понимания: Это основная форма доказательства корректности.
Частичная и полная корректностьЧастичная: если программа завершится, ответ будет верным. Полная: ответ верен и программа обязательно завершится.
Пример: зацикливающаяся программа не является полностью корректной.
Для понимания: Для полной корректности отдельно доказывают завершение.
Правила выводаДля следования связывают постусловие первой команды с предусловием второй; для ветвления доказывают обе ветви; для цикла находят инвариант.
Пример: модуль числа: отдельно доказать случаи x≥0 и x<0.
Для понимания: Нельзя проверить только «обычный» путь выполнения.
Инвариант циклаУтверждение, истинное до цикла и сохраняемое каждой итерацией; вместе с завершением даёт постусловие.
Пример: после первых k элементов max — максимум этой части.
Для понимания: Схема: инициализация → сохранение → завершение.
Процедуры и функцииИменованные подалгоритмы. Традиционно функция возвращает значение, процедура выполняет действие; в C# оба варианта — методы.
Пример: int Max(...) и void Print().
Для понимания: Подпрограммы уменьшают повторение и скрывают детали.
Параметры ref, out, inref передаёт существующую переменную по ссылке; out требует присвоения внутри; in передаёт по ссылке только для чтения.
Пример: int.TryParse(text, out int value).
Для понимания: Без модификатора сам параметр передаётся по значению.
Массив и утверждения о нёмМассив — фиксированная последовательность однотипных элементов с доступом по индексу O(1). Утверждения описывают свойства индексов и элементов.
Пример: ∀i: 0≤iДля понимания: При доказательстве явно указывают обработанный диапазон.
Записи и файлыЗапись объединяет именованные поля разных типов; файл — именованная последовательность данных во внешней памяти.
Пример: Студент: фамилия, курс, балл; журнал событий в файле.
Для понимания: В C# записи моделируют class/struct/record, файлы обрабатывают потоками.
Индуктивные функцииФункция на последовательности задаётся базой для пустого случая и правилом добавления очередного элемента.
Пример: Sum(∅)=0; Sum(x::S)=x+Sum(S).
Для понимания: Так описывают обработку списка, массива или файла любого размера.

6.3. Динамические структуры, списки, модули и рекурсия 13 терминов

Вопрос / терминКраткий ответ + пример
Динамическая структураСтруктура, размер и связи которой меняются во время выполнения; память выделяется по необходимости.
Пример: связный список растёт при добавлении узлов.
Для понимания: Динамичность относится к структуре, а не обязательно к изменяемости каждого значения.
Линейный списокУпорядоченная последовательность элементов. Может быть реализована массивом или связанными узлами.
Пример: список задач на день.
Для понимания: Список — абстракция, реализация может различаться.
Односвязный списокУзел хранит данные и ссылку на следующий элемент; движение только вперёд.
Пример: 10 → 20 → 30.
Для понимания: Удаление известного следующего узла — O(1).
Двусвязный и кольцевой списокДвусвязный хранит ссылки вперёд и назад; кольцевой связывает последний узел с первым.
Пример: переключение вкладок; круговое планирование задач.
Для понимания: Больше ссылок — больше памяти, а у кольца нужно контролировать остановку.
Массивная реализация спискаЭлементы хранятся подряд, а при заполнении создаётся больший массив и данные копируются.
Пример: List в C#.
Для понимания: Добавление в конец амортизированно O(1), отдельное расширение — O(n).
Сложность связного спискаДоступ и поиск — O(n). Вставка и удаление — O(1), только если нужный узел уже найден.
Пример: сначала найти узел O(n), затем переключить ссылку O(1).
Для понимания: Нельзя говорить «вставка всегда O(1)» без уточнения поиска позиции.
Список как АТДЗадаёт операции создания, вставки, удаления, поиска и обхода, не фиксируя способ хранения.
Пример: один интерфейс реализуют массивом или узлами.
Для понимания: Клиент зависит от поведения, а не от внутренней памяти.
Модульная программаПрограмма разделена на самостоятельные модули с чёткими интерфейсами и скрытой реализацией.
Пример: авторизация отдельно от оплаты.
Для понимания: Хороший модуль имеет одну связанную ответственность и мало зависимостей.
Рекурсивное определениеОбъект определяется через более простой объект того же вида и базовый случай.
Пример: список — пустой или голова плюс хвост.
Для понимания: Без базы определение не завершается.
Рекурсивный алгоритмВызывает себя для меньшей подзадачи; содержит базовый случай и шаг, приближающий к нему.
Пример: factorial(0)=1; factorial(n)=n·factorial(n−1).
Для понимания: Каждый вызов обычно занимает место в стеке.
Конструирование рекурсииВыделить минимальный случай, уменьшенную подзадачу, способ объединения результатов и меру, которая уменьшается.
Пример: сумма списка: 0 для пустого, иначе голова + сумма хвоста.
Для понимания: Сначала сформулируй, что возвращает рекурсивный вызов.
Верификация рекурсииКорректность доказывают индукцией: база, предположение для меньшего входа, шаг. Завершение — уменьшением меры.
Пример: для факториала предполагают правильность (n−1)! и получают n!.
Для понимания: Правильность результата и завершение — разные части доказательства.
Рекурсия и итерацияРекурсия повторяет действия через вызовы, итерация — через циклы. Многие алгоритмы допускают обе записи.
Пример: дерево удобно обходить рекурсией, массив — циклом.
Для понимания: Итерация экономит стек, рекурсия лучше отражает рекурсивную структуру.

6.4. Абстрактные типы данных, деревья и коды 13 терминов

Вопрос / терминКраткий ответ + пример
Абстрактный тип данных (АТД)Модель значений и операций над ними, независимая от конкретного хранения и кода реализации.
Пример: стек задаёт Push, Pop, Peek, но может храниться массивом или списком.
Для понимания: АТД отвечает «что можно делать?», структура данных — «как это устроено?».
Спецификация, представление, реализацияСпецификация описывает операции и их смысл; представление — внутренние данные; реализация — алгоритмы операций.
Пример: стек: контракт Pop, массив и индекс вершины, код изменения индекса.
Для понимания: Один АТД может иметь несколько реализаций.
СтекЛинейная структура LIFO: последний добавленный элемент извлекается первым. Операции Push, Pop, Peek.
Пример: стопка тарелок; стек вызовов.
Для понимания: Операции с вершиной обычно O(1).
ОчередьЛинейная структура FIFO: первым извлекается самый ранний элемент. Операции Enqueue, Dequeue, Peek.
Пример: очередь печати; BFS.
Для понимания: Добавление — в конец, извлечение — из начала.
ДекДвусторонняя очередь: добавление и удаление разрешены с обоих концов.
Пример: скользящее окно; очередь задач.
Для понимания: Может работать и как стек, и как очередь.
Иерархический списокСписок, элементами которого могут быть значения и другие вложенные списки.
Пример: [1,[2,3],[4,[5]]].
Для понимания: Удобен для выражений, документов и синтаксических структур.
Дерево и лесДерево — связная иерархия без циклов; лес — множество непересекающихся деревьев.
Пример: каталог папок; несколько независимых каталогов.
Для понимания: В дереве между двумя вершинами единственный простой путь.
Бинарное деревоДерево, где у вершины не более двух потомков: левого и правого.
Пример: дерево арифметического выражения.
Для понимания: Бинарное дерево не обязательно является деревом поиска.
Обходы дереваPreorder: корень–лево–право; inorder: лево–корень–право; postorder: лево–право–корень; по уровням — с очередью.
Пример: inorder в BST выводит ключи по возрастанию.
Для понимания: Полный обход всех n вершин занимает O(n).
Кодовое деревоПуть от корня к листу задаёт код символа; обычно левое ребро — 0, правое — 1.
Пример: путь 0–1–1 кодирует символ D.
Для понимания: Символы размещают в листьях для однозначного завершения кода.
Префиксный кодНи одно кодовое слово не является началом другого, поэтому поток декодируется без разделителей.
Пример: A=0, B=10, C=110, D=111.
Для понимания: A=0 и B=01 — плохой набор: 0 является префиксом 01.
Алгоритм ХаффманаМногократно объединяет два наименее частых узла, создавая родителя с суммарной частотой; пути образуют оптимальный префиксный код.
Пример: частый символ получает короткий код.
Для понимания: С очередью приоритетов — O(k log k) для k символов.
Оптимальный префиксный кодМинимизирует среднюю длину кодового слова при заданных частотах среди префиксных кодов.
Пример: самой частой букве дают путь ближе к корню.
Для понимания: Оптимальность относится к известному распределению частот.

6.5. Исчерпывающий и быстрый поиск 15 терминов

Вопрос / терминКраткий ответ + пример
Исчерпывающий поискИсследование всего пространства вариантов или большой его части до нахождения решения или оптимума.
Пример: перебор всех маршрутов.
Для понимания: Точен, но число вариантов часто растёт экспоненциально.
Перебор с возвратомРешение строится по частям; при нарушении ограничения последний выбор отменяется и пробуется другой.
Пример: восемь ферзей: конфликтующий ферзь снимается.
Для понимания: Отсечение происходит из-за недопустимости частичного решения.
Метод ветвей и границЗадача делится на ветви, для каждой вычисляется оценка лучшего возможного результата; ветвь отбрасывается, если не улучшит текущий лучший ответ.
Пример: маршрут уже имеет слишком большую нижнюю оценку.
Для понимания: Используется для оптимизации; худший случай всё ещё экспоненциальный.
Backtracking и ветви и границыBacktracking отсекает недопустимое; ветви и границы — допустимое, но заведомо неоптимальное.
Пример: ферзи против коммивояжёра.
Для понимания: Главное различие — причина отсечения.
Динамическое программированиеСохраняет ответы перекрывающихся подзадач и строит общий результат благодаря оптимальной подструктуре.
Пример: Фибоначчи с таблицей.
Для понимания: Мемоизация — сверху вниз, табуляция — снизу вверх.
Состояние и переход ДПСостояние хранит ответ для подзадачи, переход выражает его через более простые состояния, база задаёт начальные значения.
Пример: dp[i] — лучший результат для первых i элементов.
Для понимания: Правильный выбор состояния определяет сложность решения.
Линейный поискПоследовательно проверяет элементы до совпадения или конца.
Пример: поиск имени в неотсортированном списке.
Для понимания: Не требует сортировки; O(n).
Бинарный поискВ отсортированном массиве сравнивает с серединой и отбрасывает половину диапазона.
Пример: поиск 24 в [3,7,11,18,24,31].
Для понимания: Нужны сортировка и быстрый доступ по индексу; O(log n).
ХешированиеХеш-функция превращает ключ в индекс корзины; затем проверяются элементы этой корзины.
Пример: Dictionary.
Для понимания: Среднее O(1), худшее O(n).
КоллизияРазные ключи получают один индекс; решается цепочками или открытой адресацией.
Пример: 17 и 27 при mod 10 попадают в корзину 7.
Для понимания: Коллизии неизбежны, важно контролировать их распределение.
Бинарное дерево поискаСлева от вершины ключи меньше, справа — больше. Стоимость операций зависит от высоты.
Пример: 5 с потомками 3 и 8.
Для понимания: Среднее O(log n), вырожденное дерево — O(n).
Случайное и оптимальное деревоСлучайное BST получается случайным порядком вставки; оптимальное строится по вероятностям запросов и минимизирует среднее число сравнений.
Пример: частый ключ помещают ближе к корню.
Для понимания: Случайное балансируется статистически, оптимальное требует известных частот.
АВЛ-деревоСамобалансирующееся BST: разность высот поддеревьев каждой вершины равна −1, 0 или 1. Баланс восстанавливают поворотами.
Пример: цепочка 30–20–10 исправляется правым поворотом.
Для понимания: Поиск, вставка и удаление гарантированно O(log n).
TreapРандомизированное дерево: по ключам выполняет правило BST, по случайным приоритетам — правило кучи.
Пример: вставка по ключу, затем повороты по приоритету.
Для понимания: Ожидаемое O(log n), худшее O(n).
Анализ эффективности поискаУчитывают время, память, худший случай, необходимость порядка, стоимость вставок и предварительной сортировки.
Пример: хеш — точный ключ, АВЛ — диапазоны.
Для понимания: Лучшая структура определяется набором операций, а не одной цифрой сложности.

6.6. Сортировки и порядковые статистики 14 терминов

Вопрос / терминКраткий ответ + пример
Задача сортировкиПерестановка элементов по заданному ключу или отношению порядка без потери данных.
Пример: студентов упорядочить по баллу.
Для понимания: Ключ может состоять из нескольких полей.
УстойчивостьЭлементы с одинаковыми ключами сохраняют исходный взаимный порядок.
Пример: при равном балле сохраняется прежний порядок фамилий.
Для понимания: Важно при последовательной сортировке по нескольким полям.
Внутренняя и внешняя сортировкаВнутренняя работает, когда данные помещаются в RAM; внешняя — с большими файлами на диске и минимизирует ввод-вывод.
Пример: файл 100 ГБ сортируют частями.
Для понимания: Внешняя обычно основана на слиянии серий.
Пузырьковая сортировкаСравнивает соседей и меняет их местами; большие элементы постепенно уходят в конец.
Пример: [3,1,2] → [1,3,2] → [1,2,3].
Для понимания: O(n²), O(1) памяти, устойчива.
Сортировка выборомНаходит минимум неотсортированной части и ставит на текущую позицию.
Пример: из [4,2,3] выбрать 2.
Для понимания: O(n²), мало обменов, обычно неустойчива.
Сортировка вставкамиВставляет очередной элемент в правильное место уже отсортированного префикса.
Пример: как карты на руках.
Для понимания: Лучший O(n), худший O(n²), устойчива.
Сортировка слияниемДелит массив, сортирует половины и сливает их.
Пример: [4,1] и [3,2] → [1,4] и [2,3] → [1,2,3,4].
Для понимания: Всегда O(n log n), устойчива, O(n) памяти.
Быстрая сортировкаВыбирает опорный элемент, разделяет меньшие и большие элементы и рекурсивно сортирует части.
Пример: опора 5: 2,3 слева; 7,9 справа.
Для понимания: Среднее O(n log n), худшее O(n²), обычно неустойчива.
Пирамидальная сортировкаСтроит max-heap и поочерёдно переносит максимум из корня в конец.
Пример: наибольший элемент занимает последнюю позицию.
Для понимания: O(n log n), O(1) памяти, неустойчива.
Внешнее слияниеФайл разбивают на части, сортируют каждую в памяти, записывают серии и многократно сливают.
Пример: три отсортированных файла объединяют в один.
Для понимания: Последовательное чтение диска эффективнее случайных обращений.
Оптимальная сортировкаДля сортировок только сравнениями нижняя граница — Ω(n log n); алгоритмы с O(n log n) в худшем случае асимптотически оптимальны.
Пример: Merge Sort и Heap Sort.
Для понимания: Подсчёт и radix могут быть быстрее, потому что используют свойства ключей.
Порядковая статистикаЭлемент на позиции k в отсортированном порядке: минимум, максимум, медиана, k-й по величине.
Пример: третье по величине число.
Для понимания: Для одной статистики полная сортировка может быть лишней.
QuickselectРазбивает массив как Quick Sort, но продолжает только в части, содержащей позицию k.
Пример: поиск медианы.
Для понимания: Среднее O(n), худшее O(n²).
Выбор сортировкиУчитывают размер, память, устойчивость, исходный порядок, худший случай и место хранения данных.
Пример: Insertion — маленький почти отсортированный массив; Merge — стабильность; внешнее слияние — диск.
Для понимания: Нет алгоритма, лучшего по всем критериям.

6.7. Файлы и B-деревья 12 терминов

Вопрос / терминКраткий ответ + пример
Организация файлаСпособ логического и физического размещения записей, определяющий поиск, чтение, вставку и удаление.
Пример: журнал хранится последовательно, справочник — через индекс.
Для понимания: Организацию выбирают по наиболее частым операциям.
Запись и страницаЗапись объединяет поля одного объекта; страница или блок — единица обмена между диском и RAM, содержащая несколько записей.
Пример: СУБД читает страницу целиком ради одной строки.
Для понимания: Во внешней памяти особенно важно уменьшать число чтений страниц.
Последовательный доступЗаписи читаются по порядку; хорош для полного прохода, но поиск отдельной записи обычно O(n).
Пример: журнал событий.
Для понимания: Прост и эффективен для потоковой обработки.
Прямой доступПереход к записи по номеру или вычисляемому адресу.
Пример: base + i·L для записей фиксированной длины.
Для понимания: Удобен, когда размер записи и размещение предсказуемы.
Индексная организацияОтдельная структура связывает ключ с местом записи, ускоряя точный и диапазонный поиск.
Пример: предметный указатель фамилий.
Для понимания: Индекс занимает место и обновляется вместе с файлом.
Хешированная организацияКорзина записи вычисляется хеш-функцией от ключа; эффективна для равенства.
Пример: bucket=id mod 100.
Для понимания: Не сохраняет порядок и неудобна для диапазонов.
B-деревоСбалансированное многопутевое дерево поиска: узел содержит несколько отсортированных ключей и много потомков, все листья на одной глубине.
Пример: [20|40] делит значения на три диапазона.
Для понимания: Широкие узлы уменьшают высоту и число обращений к диску.
Поиск в B-деревеВ узле ключ сравнивается с несколькими границами, затем выбирается один подходящий потомок.
Пример: 30 между 20 и 40 — перейти в средний потомок.
Для понимания: Число чтений страниц имеет логарифмический порядок.
ВставкаКлюч помещают в подходящий лист; переполненный узел расщепляют, средний ключ поднимают к родителю.
Пример: переполненный лист делится на два.
Для понимания: Расщепление может дойти до корня и увеличить высоту.
УдалениеПри недостатке ключей выполняют перераспределение с соседом или слияние узлов через ключ родителя.
Пример: пустеющий лист объединяется с соседним.
Для понимания: Нужно сохранить заполненность и одинаковую глубину листьев.
B-дерево и BSTBST хранит обычно один ключ и до двух потомков; B-дерево — много ключей и потомков и всегда сбалансировано.
Пример: BST удобен в RAM, B-дерево — для дискового индекса.
Для понимания: Главное преимущество B-дерева — мало операций ввода-вывода.
B+‑дерево — дополнениеОсновные записи находятся в листьях, внутренние узлы служат навигации, а листья часто связаны цепочкой.
Пример: последовательное чтение диапазона дат.
Для понимания: Полезно для понимания индексов СУБД, но официальный пункт называет B-дерево.

6.8. Представления графов и основные алгоритмы 16 терминов

Вопрос / терминКраткий ответ + пример
ГрафСтруктура G=(V,E), где V — вершины, E — рёбра между ними. Бывает ориентированным/неориентированным и взвешенным/невзвешенным.
Пример: города и дороги.
Для понимания: Тип графа определяет допустимые алгоритмы.
Матрица смежностиТаблица V×V, где ячейка хранит наличие или вес ребра.
Пример: A[i,j]=1, если связь есть.
Для понимания: Память O(V²), проверка ребра O(1); удобна для плотных графов.
Список смежностиДля каждой вершины хранится список соседей и весов.
Пример: A: B,C; B: A,D.
Для понимания: Память O(V+E); удобен для разреженных графов.
Список рёбер и матрица инцидентностиСписок рёбер хранит пары/тройки вершин; матрица инцидентности связывает строки-вершины со столбцами-рёбрами.
Пример: (A,B,4) удобно для Краскала.
Для понимания: Список рёбер компактен, инцидентность полезна в формальных задачах.
BFS — поиск в ширинуОбходит граф по уровням с помощью очереди; сначала ближайшие вершины, затем более далёкие.
Пример: минимальное число пересадок.
Для понимания: O(V+E) со списками смежности.
Почему BFS находит кратчайший путьВ невзвешенном графе первое посещение вершины происходит по минимальному числу рёбер от старта.
Пример: сначала расстояние 1, затем 2.
Для понимания: Для разных весов нужен другой алгоритм.
DFS — поиск в глубинуИдёт по ветви максимально глубоко и возвращается из тупика; использует стек или рекурсию.
Пример: обход лабиринта.
Для понимания: O(V+E); циклы, компоненты, топологическая сортировка.
Остовное деревоСвязный подграф, содержащий все вершины, не имеющий циклов и имеющий V−1 ребро.
Пример: связать корпуса без лишнего кольца.
Для понимания: Удаление любого ребра нарушает связность.
Минимальное остовное деревоОстов с минимальной общей суммой весов.
Пример: самая дешёвая прокладка кабелей.
Для понимания: Не обязано давать кратчайшие пути между каждой парой вершин.
Алгоритм ПримаРастит одно дерево: выбирает минимальное ребро из построенной части к новой вершине.
Пример: расширение сети от одного корпуса.
Для понимания: С очередью приоритетов примерно O(E log V).
Алгоритм КраскалаСортирует рёбра и добавляет их по возрастанию, если не возникает цикл.
Пример: сначала все рёбра веса 1.
Для понимания: С DSU — O(E log E) из-за сортировки.
Кратчайший путьПуть между выбранными вершинами с минимальной суммой весов.
Пример: самый быстрый маршрут A→D.
Для понимания: Это не задача соединения всех вершин.
Алгоритм ДейкстрыСтарту задаёт 0, остальным бесконечность; выбирает минимальную необработанную вершину и релаксирует её рёбра. Требует неотрицательных весов.
Пример: дороги с положительным временем.
Для понимания: O((V+E) log V) с кучей.
РелаксацияПроверка, лучше ли путь до v через u: d[v]=min(d[v],d[u]+w(u,v)).
Пример: было 10, через соседа 7 — записать 7.
Для понимания: Это обновление расстояния, а не построение остова.
Беллман—ФордРелаксирует все рёбра V−1 раз; допускает отрицательные веса и дополнительным проходом обнаруживает отрицательный цикл.
Пример: граф с отрицательной стоимостью.
Для понимания: O(VE), поэтому медленнее Дейкстры.
BFS, Дейкстра и остовBFS — кратчайший путь без весов; Дейкстра — с неотрицательными весами; Прим/Краскал — минимальная общая связь всех вершин.
Пример: пересадки, навигатор, прокладка сети.
Для понимания: Не смешивай «кратчайший маршрут» и «дешёвую общую сеть».

6.9. Теория сложности и NP-сложность 15 терминов

Вопрос / терминКраткий ответ + пример
Размер входаКоличество данных, относительно которого оценивают затраты алгоритма.
Пример: для массива — n элементов, для графа — V и E, для числа — число битов.
Для понимания: Сложность зависит от длины представления входа.
Временная и пространственная сложностьВременная оценивает рост числа операций, пространственная — дополнительную память.
Пример: проход O(n), Merge Sort использует O(n) памяти.
Для понимания: О-нотация отбрасывает константы и младшие члены.
Полиномиальное времяВремя O(n^k) для постоянного k; условно считается масштабируемым.
Пример: O(n), O(n log n), O(n³).
Для понимания: 2^n и n! растут намного быстрее.
Задача принятия решенийЗадача с ответом «да/нет»; именно для таких задач формально определяют P и NP.
Пример: «Есть ли маршрут не дороже K?»
Для понимания: Оптимизационную задачу связывают с решающей версией.
Класс PЗадачи принятия решений, решаемые детерминированным алгоритмом за полиномиальное время.
Пример: проверка связности через BFS.
Для понимания: Коротко: можно быстро решить.
Класс NPЗадачи, для которых положительный ответ с сертификатом можно проверить за полиномиальное время.
Пример: предложенный гамильтонов путь.
Для понимания: NP не означает «неполиномиальные»; P ⊆ NP.
СертификатДанные, подтверждающие ответ «да» и допускающие быструю проверку.
Пример: маршрут, раскраска, набор выбранных предметов.
Для понимания: Проверяющий не обязан сам находить сертификат.
P и NPИзвестно P ⊆ NP, но неизвестно, верно ли P=NP.
Пример: быстро решить ⇒ быстро проверить, обратное не доказано.
Для понимания: Нельзя говорить, что P≠NP уже доказано.
Полиномиальное сведениеA≤pB: экземпляр A быстро преобразуется в B, и ответы совпадают.
Пример: решатель B позволяет решить A.
Для понимания: Для трудности новой B известную трудную A сводят к B.
NP-трудная задачаНе менее трудна, чем любая задача NP; не обязана сама быть задачей «да/нет» или принадлежать NP.
Пример: оптимизационный коммивояжёр.
Для понимания: NP-трудность шире NP-полноты.
NP-полная задачаОдновременно принадлежит NP и является NP-трудной.
Пример: SAT, 3-SAT, гамильтонов путь.
Для понимания: Полиномиальный алгоритм для одной такой задачи дал бы P=NP.
Как доказать NP-полнотуПоказать принадлежность NP, затем свести известную NP-полную задачу к новой за полиномиальное время.
Пример: 3-SAT≤pНоваяЗадача.
Для понимания: Важны направление сведения и эквивалентность ответов.
Труднорешаемая задачаАлгоритм существует, но точное решение может требовать непрактично больших ресурсов.
Пример: перебор n! маршрутов.
Для понимания: Малые экземпляры всё же могут решаться быстро.
Неразрешимая задачаНе существует алгоритма, всегда завершающегося и правильно отвечающего на всех входах.
Пример: общая проблема остановки.
Для понимания: NP-сложность — вопрос ресурсов; неразрешимость — принципиальная невозможность.
Практические методыПеребор с отсечениями, динамическое программирование, ветви и границы, приближённые алгоритмы и эвристики.
Пример: быстро найти хороший, но не гарантированно лучший маршрут.
Для понимания: Выбор зависит от требования точности и доступного времени.

6.10. Функциональное программирование и лямбда-исчисление 22 терминов

Вопрос / терминКраткий ответ + пример
Функциональное программированиеПарадигма, где вычисление представляется как применение функций к значениям, а функции можно хранить, передавать и возвращать.
Пример: filter → map → fold для обработки списка.
Для понимания: Акцент на результате выражений, а не на последовательном изменении состояния.
Функция как значениеФункцию можно присвоить переменной, передать аргументом, вернуть из другой функции или хранить в структуре данных.
Пример: передать функцию сравнения в сортировку.
Для понимания: Это основа функций высшего порядка и композиции.
Чистая функцияПри одинаковых аргументах всегда возвращает одинаковый результат и не изменяет внешнее состояние.
Пример: square(x)=x*x.
Для понимания: Её легче тестировать и выполнять параллельно.
Побочный эффектДействие помимо вычисления результата: запись в файл, вывод, сеть, изменение объекта или глобальной переменной.
Пример: увеличение глобального счётчика.
Для понимания: Практические программы используют эффекты, но чистую логику полезно отделять.
Неизменяемые данныеПосле создания значение не меняется; операция создаёт новое значение, часто переиспользуя неизменённые части.
Пример: добавление к списку F# создаёт новый список.
Для понимания: Уменьшаются скрытые зависимости и гонки данных.
Функции высшего порядкаПринимают другие функции или возвращают их.
Пример: List.map (fun x -> x*x).
Для понимания: Позволяют отделить общий обход от конкретного действия.
map, filter, foldmap преобразует каждый элемент; filter оставляет элементы по условию; fold накапливает один результат с начальным аккумулятором.
Пример: чётные → квадраты → сумма.
Для понимания: Это основные операции функциональной обработки коллекций.
fold и reducefold имеет явный начальный аккумулятор; reduce использует первый элемент коллекции.
Пример: fold (+) 0 [1;2;3] = 6.
Для понимания: fold можно применить к пустой коллекции, reduce — нет.
Рекурсивная функцияВызывает себя для меньшего аргумента и содержит базовый случай.
Пример: факториал, обход дерева.
Для понимания: В функциональном стиле рекурсия часто заменяет изменяемые циклы.
Хвостовая рекурсияРекурсивный вызов является последней операцией, поэтому реализация может переиспользовать кадр стека.
Пример: сумма списка с аккумулятором.
Для понимания: Если после вызова ещё нужно умножение, рекурсия не хвостовая.
Лямбда-исчислениеМинимальная математическая модель вычислений из переменных, абстракции и применения функций.
Пример: λx.x+1.
Для понимания: Теоретическая основа функциональных языков.
Лямбда-абстракцияЗапись λx.M создаёт анонимную функцию с параметром x и телом M.
Пример: λx.x²; в F# — fun x -> x*x.
Для понимания: Параметр связан внутри тела функции.
Применение и бета-редукцияПрименение функции к аргументу выполняется подстановкой аргумента вместо параметра.
Пример: (λx.x+1) 5 → 6.
Для понимания: Бета-редукция моделирует вычисление выражения.
Сопоставление с образцомВыбор ветви по форме значения с одновременным извлечением его частей.
Пример: пустой список отдельно от head::tail.
Для понимания: Нужен полный набор вариантов или случай по умолчанию.
Размеченное объединениеТип, значение которого является одним из перечисленных вариантов с собственными данными.
Пример: Circle radius | Rectangle(width,height).
Для понимания: Удобно моделирует состояния, результаты и деревья.
Функциональные языкиПоддерживают функции как значения, рекурсию, композицию и неизменяемые структуры.
Пример: F#, Haskell, Lisp, OCaml.
Для понимания: Языки различаются по чистоте и стратегии вычисления.
Чистый функциональный языкИзменяемое состояние и побочные эффекты строго контролируются, обычные выражения ведут себя как математические функции.
Пример: Haskell.
Для понимания: Не путать чистоту с немедленным вычислением аргументов.
Строгие и ленивые вычисленияСтрогая стратегия вычисляет аргументы заранее; ленивая — только при необходимости.
Пример: бесконечная последовательность обрабатывается по требованию.
Для понимания: Ленивость экономит работу, но усложняет оценку памяти.
Представление и интерпретацияПрограмма разбирается в дерево выражений; интерпретатор выполняет редукции, компилятор переводит выражения в промежуточный или машинный код.
Пример: square(2+3) — применение функции к выражению суммы.
Для понимания: Нужны замыкания, сборка мусора и поддержка вызовов функций.
Отладка функциональных программИспользуют типизацию, REPL, модульные тесты чистых функций, малые примеры и проверку полноты pattern matching.
Пример: проверить сортировку на пустом и одном элементе.
Для понимания: Чистота уменьшает число скрытых состояний.
Функциональная и императивная программаИмперативная задаёт команды и изменение состояния; функциональная — композицию преобразований значений.
Пример: цикл с переменной sum против fold.
Для понимания: Одну задачу можно выразить обоими стилями.
ПрименениеОбработка данных, компиляторы, параллельные вычисления, финансовые модели и серверные системы.
Пример: pipeline очистки и агрегации.
Для понимания: Сильная сторона — композиция и предсказуемость.

6.11. Логическое программирование, Prolog и ограничения 23 терминов

Вопрос / терминКраткий ответ + пример
Логическое программированиеПарадигма, где задаются факты и правила, а система выводит ответы на запросы.
Пример: описать родство и спросить, кто дедушка.
Для понимания: Программа описывает, что истинно, а интерпретатор ищет доказательство.
ФактБезусловно заданное истинное отношение.
Пример: parent(alex,ivan).
Для понимания: Факт похож на запись базы знаний.
ПравилоУсловное утверждение: заголовок истинен, если доказаны цели в теле.
Пример: grandparent(X,Z) :- parent(X,Y), parent(Y,Z).
Для понимания: Запятая означает логическое «и» и порядок подцелей.
ЗапросЦель, которую система пытается доказать, подбирая значения переменных.
Пример: ?- grandparent(alex,Who).
Для понимания: Ответом может быть истина, ложь или несколько подстановок.
ТермОсновная структура данных: переменная, атом, число, составной терм или список.
Пример: student(alex,22) — функтор student, арность 2.
Для понимания: Данные и программа имеют сходное термовое представление.
УнификацияПодбор подстановок, при которых два терма становятся одинаковыми.
Пример: point(X,20) и point(10,Y) дают X=10, Y=20.
Для понимания: Это согласование, а не обычное переназначение переменной.
Декларативная семантикаЛогический смысл программы независимо от конкретного поиска.
Пример: предок определяется через родителя.
Для понимания: Отвечает на вопрос «что означает программа?».
Операционная семантикаКак система реально выбирает правила, унифицирует цели, создаёт точки выбора и возвращается.
Пример: Prolog обычно идёт сверху вниз, слева направо, в глубину.
Для понимания: Порядок правил влияет на скорость и завершение.
Вычислительная модельЦель унифицируется с фактом или правилом, заменяется телом правила, затем доказываются подцели; используются SLD-резолюция и backtracking.
Пример: запрос предка раскрывается в два parent.
Для понимания: Поиск строит доказательство, а не выполняет обычные присваивания.
Недетерминизм и backtrackingПредикат может дать несколько решений; при неудаче или запросе следующего ответа система возвращается к точке выбора.
Пример: color(red), color(green) дают два X.
Для понимания: Недетерминизм — множество вариантов, не случайность.
КорректностьВсе выдаваемые ответы должны логически следовать из программы; полнота требует получения всех нужных ответов при выбранной стратегии.
Пример: правило не должно выводить ложное родство.
Для понимания: Логическая корректность не гарантирует завершение.
Логическая база данныхФакты представляют записи, правила — производные отношения, запросы — выборку.
Пример: student(alex,group41).
Для понимания: Особенно удобны рекурсивные отношения.
Рекурсивное программированиеОтношение задаётся базовым и рекурсивным правилами через более короткую цепочку.
Пример: предок — родитель или родитель предка.
Для понимания: Базовый случай должен быть достижим.
Металогические предикатыРаботают с целями, переменными и структурой вычисления как с данными.
Пример: call(Goal), var(X), findall.
Для понимания: Основа метапрограммирования.
Внелогические предикатыЗависят от состояния выполнения и не являются чистыми отношениями.
Пример: ввод-вывод, отсечение !, изменение базы.
Для понимания: Практичны, но уменьшают декларативность.
Отсечение !Запрещает возврат к части ранее созданных альтернатив.
Пример: после выбора подходящего правила не пробовать следующие.
Для понимания: Неправильное отсечение может изменить множество ответов.
Неполные структуры данныхТермы со свободными переменными, которые достраиваются унификацией.
Пример: [a,b|Tail].
Для понимания: Можно одновременно строить и анализировать структуру.
Программирование второго порядкаПредикаты передаются другим предикатам как аргументы и вызываются через мета-вызов.
Пример: maplist(double,Input,Output).
Для понимания: Аналог функций высшего порядка.
Методы поискаСтандартный Prolog использует DFS и возврат; возможны BFS, итеративное углубление, эвристики и табулирование.
Пример: кратчайший план удобнее искать BFS.
Для понимания: Стратегия влияет на полноту и завершение.
Constraint-PrologПеременным задают домены и ограничения; система распространяет их, сужает варианты и затем выбирает значения.
Пример: X in 1..10, Y in 1..10, X+Y #= 10.
Для понимания: Сначала отбрасываются несовместимые значения.
Операционная семантика CLPОграничение добавляется в хранилище, сужает домены, изменения распространяются; затем выполняется labeling или другой поиск.
Пример: из XДля понимания: Переменные могут оставаться символическими до конца.
Нечёткие данныеИстинность или принадлежность задаётся степенью от 0 до 1.
Пример: «температура высокая» = 0,7.
Для понимания: Нечёткость описывает плавность понятия, а не вероятность события.
Применение в ИИЭкспертные системы, представление знаний, планирование, диагностика, доказательство теорем и задачи ограничений.
Пример: подбор диагноза по фактам и правилам.
Для понимания: Плюс — объяснимый логический вывод.

6.12. Объектно-ориентированное программирование и проектирование 26 терминов

Вопрос / терминКраткий ответ + пример
Объектно-ориентированное программированиеПарадигма, где программа — система взаимодействующих объектов, объединяющих состояние и поведение.
Пример: Заказ, Товар, Клиент и Оплата.
Для понимания: Объекты взаимодействуют через методы и сообщения.
ОбъектКонкретная сущность с идентичностью, состоянием и поведением.
Пример: конкретный банковский счёт.
Для понимания: Состояние меняется, идентичность сохраняется.
КлассОписание типа объектов: полей, свойств, методов, конструкторов и правил поведения.
Пример: BankAccount — класс, конкретный счёт — объект.
Для понимания: Класс задаёт шаблон множества экземпляров.
Данные и методыПоля и свойства хранят состояние; методы реализуют действия и правила его изменения.
Пример: Balance и Deposit.
Для понимания: Хороший объект защищает собственные инварианты.
АбстракцияВыделение существенных свойств и сокрытие неважных деталей.
Пример: водитель использует руль и педали, не управляя впрыском.
Для понимания: Абстракция создаёт удобную модель.
ИнкапсуляцияОбъединение данных и методов с ограничением прямого доступа к внутреннему состоянию.
Пример: Balance { get; private set; }.
Для понимания: Цель — не позволить нарушить допустимое состояние.
Модификаторы доступаpublic — всем; private — внутри класса; protected — классу и потомкам; internal — внутри сборки.
Пример: служебный метод делают private.
Для понимания: Принцип минимально необходимого доступа.
НаследованиеПроизводный класс повторно использует и специализирует базовый; выражает отношение «является».
Пример: Developer : Employee.
Для понимания: C# допускает один базовый класс и несколько интерфейсов.
ПереопределениеПотомок заменяет реализацию virtual/abstract метода, сохраняя контракт.
Пример: override CalculateSalary().
Для понимания: Выбор идёт по фактическому типу объекта.
ПерегрузкаМетоды одного имени имеют разные параметры; вариант выбирает компилятор.
Пример: Add(int,int) и Add(double,double).
Для понимания: Перегрузка — статический, переопределение — динамический полиморфизм.
ПолиморфизмОбъекты разных типов используются через общий базовый тип или интерфейс и по-разному выполняют общий метод.
Пример: разные IShape вычисляют площадь.
Для понимания: Клиент не проверяет каждый конкретный класс вручную.
ИнтерфейсКонтракт операций, которые должен поддерживать тип, без обязательной общей реализации и состояния.
Пример: INotifier реализуют Email и SMS.
Для понимания: Уменьшает зависимость от конкретного класса.
Абстрактный классНеполный базовый класс с состоянием, конструктором, готовыми и абстрактными методами; напрямую не создаётся.
Пример: abstract Shape.
Для понимания: Подходит для семейства с общей реализацией.
Интерфейс и абстрактный классИнтерфейс описывает роль и допускает несколько реализаций; абстрактный класс даёт общую основу и состояние.
Пример: ILogger для несвязанных классов.
Для понимания: Класс наследует один класс, но реализует несколько интерфейсов.
Ассоциация, агрегация, композицияАссоциация — общее отношение; агрегация — часть может жить отдельно; композиция — часть разделяет жизненный цикл целого.
Пример: преподаватель–курс; команда–игрок; заказ–строка заказа.
Для понимания: Композиция означает сильное владение.
ЗависимостьКратковременное использование объекта через параметр или локальную переменную.
Пример: ReportService получает IPrinter.
Для понимания: Слабее постоянной ассоциации.
Система объектов и классовКлассы предметной области, сервисы и интерфейсы совместно выполняют сценарии программы.
Пример: OrderService координирует Order, Payment и Notifier.
Для понимания: Обязанности нужно распределять, а не собирать в God Object.
Проектирование ОО-программыТребования → сущности и обязанности → классы, данные и методы → связи → интерфейсы → алгоритмы → тестирование и рефакторинг.
Пример: из оформления заказа выделяют Корзину, Платёж, Уведомление.
Для понимания: Класс должен иметь ясную ответственность.
UMLДиаграммы классов показывают структуру; последовательности — сообщения; состояний — переходы; вариантов использования — функции для акторов.
Пример: Заказ—Клиент—Товар.
Для понимания: UML помогает обсуждению, но не заменяет требования и код.
Паттерны проектированияПовторяемые идеи решения типовых проблем: Factory, Strategy, Observer, Adapter и другие.
Пример: Strategy заменяет алгоритм оплаты.
Для понимания: Паттерн применяют при реальной проблеме, а не ради сложности.
Классификация ОО-языковКлассовые и прототипные; статически и динамически типизированные; с одиночным или множественным наследованием; компилируемые или интерпретируемые.
Пример: C# — классовый, статически типизированный, .NET.
Для понимания: Один язык описывается сразу несколькими признаками.
Архитектура ОО-системыСистема делится на слои и компоненты, внутри которых объекты взаимодействуют через интерфейсы.
Пример: UI → сервисы → предметная область → данные.
Для понимания: Архитектура задаёт крупные зависимости, классы — внутреннюю структуру.
Выразительные средстваКлассы, свойства, методы, конструкторы, доступ, наследование, интерфейсы, виртуальные методы, обобщения, исключения и события.
Пример: событие уведомляет подписчиков.
Для понимания: Средства языка поддерживают инкапсуляцию и расширение.
Хороший интерфейсНебольшой, связный по смыслу, стабильно названный, скрывающий внутреннее устройство и не заставляющий клиента зависеть от лишних операций.
Пример: IReadable отдельно от IWritable.
Для понимания: Лучше несколько узких контрактов, чем один огромный.
Наследование и композицияНаследование — «является», композиция — «содержит/использует».
Пример: Dog является Animal; Car содержит Engine.
Для понимания: Композиция обычно гибче и создаёт более слабую связь.
Плюсы и ограничения ООППлюсы: моделирование предметной области, инкапсуляция, модульность, расширяемость. Минусы: множество классов, сложные связи и риск чрезмерного проектирования.
Пример: бизнес-система выигрывает, простая формула — нет.
Для понимания: ООП полезно при ясных обязанностях и контрактах.
